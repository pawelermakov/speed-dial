# SpeedDial X

Новая вкладка с визуальными закладками для Chrome и Firefox. Перенесена с Web SQL на WXT, Vue 3 (Composition API), TypeScript, Tailwind CSS 4 и IndexedDB (Dexie). Исходная реализация сохранена в Git-истории (коммит `fbd22f4bf18f72b8be6c27c7e6e895c4092a6a44`); для работы, сборки и тестов отдельная ветка не требуется.

## Возможности

- Добавление, изменение и удаление закладок, переход в текущей/новой вкладке.
- Скриншоты сайтов и обновление эскиза без изменения собственного заголовка; при ошибке сайт можно сохранить без эскиза.
- Перетаскивание карточек с транзакционным сохранением порядка.
- Поиск Яндекса, подсказки с выбором мышью, стрелками и Enter.
- Иконка Mail.ru и число непрочитанных писем для указанного E-mail.
- Правая панель: ширина 50–100%, 2–12 колонок, расстояние 0–48 px, вертикальное центрирование, кнопка «+», локальное изображение фона.
- Импорт старого JSON из файла/текста, экспорт в текст/файл, подтверждение замены и удаления всех данных.
- Адаптивная сетка, клавиатурный фокус, Escape, диалоги с удержанием фокуса.

## Установка и сборка

Node.js **22.12+** (рекомендуется Node.js 24 LTS), npm 10+. WXT 0.21.4 требует Node.js >=22; Vite 8 требует >=22.12 (или совместимую более новую ветку). Проверено с Node.js 24.19.0 и npm 10.8.2. Первичная установка актуальных зависимостей выполнена npm 12.2.0: npm 10 выдал внутреннюю ошибку `edgesOut` при создании lockfile; последующий `npm ci` с npm 10 прошёл.

```sh
npm ci
npm run dev
npm run dev:firefox
npm run compile
npm test
npm run build
npm run build:firefox
```

Корневой `manifest.json` основан на старой версии и содержит актуальные пути Chrome MV3. WXT использует его общие поля через `wxt.config.ts`, формирует точки входа и адаптирует манифест для Firefox. Для установки используйте готовую папку сборки.

WXT открывает выбранный браузер в режиме разработки. Производственные сборки:

- Chrome MV3: `.output/chrome-mv3`.
- Firefox MV2: `.output/firefox-mv2` (актуальная версия Firefox 140+).
- Архивы при необходимости: `npm run zip`, `npm run zip:firefox`.

В Chrome: `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» → папка Chrome-сборки.

В Firefox: `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение» → `manifest.json` Firefox-сборки. Временное дополнение исчезает после закрытия браузера; для повторного тестирования загрузите его снова. Постоянная установка обычным Firefox требует подписанного XPI; проект не публикует и не подписывает расширение автоматически. Gecko ID: `speed-dial-x@pawelermakov.github.io`.

## Старые данные и импорт

Web SQL удалён из Chromium начиная с Chrome 119 и отсутствовал в Firefox. Автоматического чтения исторических Web SQL-закладок здесь нет. Восстановление: «Настройки» → «Импорт» → старый `export.json` или вставка JSON → подтверждение замены. Если экспорт ещё не сделан, сохраните исходный профиль и получите экспорт из доступной старой версии браузера/расширения; обновление не умеет реконструировать удалённую БД.

Поддерживается прежний контракт `{ tabs: [...], settings: {...} }`, строковые числа и булевы значения (`"false"` означает false), отсутствующие настройки, пустой список, data URL фона/эскизов. Отсутствующие/дублирующиеся ID получают стабильные новые номера; порядок нормализуется в 1…N. Небезопасные URL и некорректные данные отклоняются до изменений. Импорт не открывает сайты автоматически.

Экспорт сохраняет URL, заголовки, favicon, ID, порядок, все настройки и пользовательский фон. **Эскизы исключаются**, как в старой версии, без изменения сохранённых карточек. После импорта обновляйте нужные эскизы через меню карточки. Растровый фон/эскиз в импорте — до 20 МБ; файл JSON — до 100 МБ, до 10000 карточек. SVG и исполняемые URL запрещены.

Если сохранён прежний extension ID/origin, при первом запуске доступные старые `localStorage`-настройки переносятся однократно. Старые ключи не очищаются. Маркер переноса хранится вместе с новым объектом настроек; сброс не запускает повторный перенос старого фона. При ошибке переноса исходные данные остаются, показывается сообщение; можно импортировать JSON. **Два разных extension ID имеют разные хранилища** — новая unpacked-установка не получает автоматически данные старого ID.

Закладки, эскизы (Blob) и фон (Blob) находятся в IndexedDB; небольшие настройки — в локальном WXT Storage. Для замены данных используется одна IDB-транзакция и журнал целевых настроек. При обычном отказе Storage IDB восстанавливается из snapshot; после прерывания процесса журнал завершает перенос настроек при следующем запуске. Это протокол восстановления, а не распределённая атомарность. Web Locks сериализуют операции нескольких новых вкладок, BroadcastChannel обновляет открытые страницы.

## Разрешения и сеть

- `storage`: локальное сохранение настроек WXT.
- `tabs`: временная вкладка, её URL, title/favicon, проверка активности и открытие ссылки в новой вкладке.
- `<all_urls>`: автоматический `captureVisibleTab` для произвольного HTTP/HTTPS-сайта. Также разрешает запросы к `suggest.yandex.ru` и `portal.mail.ru`. В Firefox MV2 WXT помещает это разрешение в `permissions`.
- `unlimitedStorage`: пользовательские изображения и эскизы в IndexedDB. Последние два разрешения сохранены из старого манифеста.
- Firefox декларирует поисковые запросы, E-mail и адреса открываемых сайтов в `data_collection_permissions`; это соответствует запросам Яндекса/Mail.ru и открытию сайта для снимка. Данные закладок/фон не отправляются в сервис синхронизации; сервера расширения нет.

Email передаётся только Mail.ru. Запрос использует браузерные cookies выбранного сервиса, без сохранения паролей/токенов и без постоянного polling. Проверка происходит при загрузке страницы и применении настроек. При пустом email значка нет, при нуле бейджа нет, при отказе/неизвестном ответе счётчик скрыт, причина доступна при наведении/фокусе значка.

Проверка 11 октября 2026: подсказки Яндекса возвращают HTTP 200 и прежний массив; доступ из реальных Chrome/Firefox-сборок проверен smoke-тестом. Прежний `https://www.yandex.ru/yandsearch?text=...` сохранён; публичный запрос может показывать CAPTCHA Яндекса. Mail.ru возвращает HTTP 200 и `status: noauth` в чистом неавторизованном профиле. Получение ненулевого счётчика из личной сессии не подтверждено: тесты не используют личные cookies/email. На счётчик могут влиять авторизация, SameSite, контейнеры и блокировка cookies Firefox.

## Захват экрана

Добавление/обновление явно сообщает, что сайт временно откроется **активной вкладкой**. Снимок показывает только видимую область, а не полную страницу. Очередь сериализует захваты; тайм-аут загрузки — 20 секунд, ожидания ответа UI вместе с очередью — 45 секунд. Подключение UI отменяет работу при закрытии вкладки. Скриншот JPEG quality 80 хранится Blob в IndexedDB, object URL освобождаются.

Перед/после захвата проверяется ID активной вкладки, URL и состояние загрузки; переключение/навигация отменяет снимок. Код закрывает только ID вкладки, созданной этой операцией, и возвращает исходную вкладку, если пользователь не переключился. Первоначальный Firefox `about:blank` не принимается за загруженный сайт. Лимит API соблюдён интервалом между захватами.

Недоступные сайты, внутренние схемы, ошибки разрешений, редиректы на запрещённые страницы, SPA/дозагрузка могут не дать эскиз. В таком случае можно сохранить URL без снимка; ошибка обновления сохраняет прежний эскиз. При принудительном завершении браузера/фонового процесса ОС может не выполнить `finally` и оставить временную вкладку: приложение не пытается закрывать произвольные вкладки после перезапуска. Сохранённые данные от жизни MV3-worker не зависят.

## Проверки

```sh
npm ci
npm run compile
npm test
npm run build
npm run build:firefox
npm audit --omit=dev

# Один раз загрузить изолированные тестовые браузеры:
npx playwright install chromium firefox
npm run test:smoke
# Отдельные платформы:
npm run test:smoke -- --chrome-only
npm run test:smoke -- --firefox-only
```

Smoke запускает реальное расширение в Chrome for Testing и Firefox из Playwright, локальный HTTP-сайт для захвата и отдельные профили внутри игнорируемой `.browser-test/`. Chrome использует Playwright; Firefox — штатный Marionette/Addon:Install, поскольку Playwright не управляет `moz-extension`-страницей в этом окружении. Тест не подключается к пользовательскому профилю. Firefox-драйвер включает system access только для тестового процесса. Результаты и PNG находятся в `.browser-test/` и не коммитятся.

Подробная матрица и ограничения: [docs/verification.md](docs/verification.md). Дополнительного линтера в стартере нет; выполняются strict TypeScript, Vitest, сборки, browser smoke и `git diff --check`.

В инструментах разработки остаётся известная транзитивная уязвимость `node-forge@1.4.0` через `web-ext/@devicefarmer/adbkit`; исправленного npm-релиза на дату проверки нет. Уязвимость не входит в production-сборку; Android/ADB здесь не используется. Исправленная `shell-quote@1.12.0` закреплена overrides. Не применяйте `npm audit fix --force`: предлагается откат WXT/web-ext с несовместимым изменением стека.

## Обновление WXT

Прочитайте [release notes](https://github.com/wxt-dev/wxt/releases) и [upgrade guide](https://wxt.dev/guide/resources/upgrading), затем:

```sh
npm install -D wxt@latest
npm run compile
npm test
npm run build
npm run build:firefox
npm run test:smoke
```

Для несовместимых переходов следуйте порядку из upgrade guide, обновите требуемые Node.js/Vue-модули и закоммитьте `package-lock.json`. Проверьте обе новые вкладки вручную и разрешения сгенерированных манифестов.

## Короткая ручная проверка

1. Загрузите соответствующую сборку и откройте новую вкладку браузерной кнопкой «+».
2. Добавьте свой HTTPS-сайт, убедитесь в его эскизе. Во время второго захвата переключитесь на другую вкладку: чужой экран не должен сохраниться.
3. Измените заголовок, обновите эскиз, переместите карточки начало/середина/конец; перезапустите браузер, проверьте порядок и фон.
4. Включите/выключите центрирование и «+», проверьте нулевое расстояние. Импортируйте свой старый JSON, сохраните новый экспорт с фоном.
5. Проверьте Enter, клик и стрелки в подсказках Яндекса; повторите без сети.
6. Для личного Mail.ru войдите в почту, укажите свой email, сохраните настройки; проверьте ненулевой счётчик, затем 0 и выход из аккаунта.
7. Откажитесь от удаления/импорта и проверьте сохранность карточек; подтвердите сброс только в тестовом профиле.

Никаких push, релизов, публикации и подписания эта миграция не выполняет.

## Проверка сходства со старой версией

Оформление восстановлено по исходной версии: размеры, шрифты, прозрачность, тени, поиск, карточки, значок почты, меню, окна и панель настроек. Настройки доступны через контекстное меню страницы, как раньше; также есть доступная с клавиатуры кнопка. Сетка сохраняет выбранное число колонок и на узком экране, как в оригинале. Центрирование применяется только к закладкам под поиском.

После `npm run build` запустите `npm run test:visual`. Нужен установленный Chrome for Testing из Playwright (`npx playwright install chromium`). Скрипт сравнивает реальное расширение с фиксированными эталонными PNG в `tests/fixtures/visual` при одинаковых тестовых данных: сетка на 360/1280/1920 px, настройки, меню, добавление/редактирование, импорт/экспорт, подсказки и почта. Тест не читает Git и не загружает старые HTML/CSS/JavaScript. Эталонные изображения имеют SHA-256 и описание происхождения в `provenance.json`; они получены на Windows с Chrome for Testing, поэтому на другой ОС/шрифтах может потребоваться отдельный проверенный эталон. Снимки и результат лежат в игнорируемой `.browser-test/visual-parity/`. Допуск сглаживания — 16 из 255 на канал, не более четырёх отличающихся пикселей на снимок.

Оформление реализовано утилитами Tailwind v4, включая произвольные значения, состояния, псевдоэлементы и backdrop. Общие классы кнопок, полей и выбора файла находятся в `utils/ui.ts`. В `assets/style.css` остались только импорт Tailwind и `@theme` с токеном цвета и keyframes для Tailwind-анимаций; обычных CSS-селекторов приложения нет. Семантические классы сохранены как DOM-хуки для проверок.
