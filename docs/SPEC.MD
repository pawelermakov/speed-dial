## F01 · P0 · Выполнена · Цветные текстовые плитки в стиле Opera

### Цель и границы

При отсутствии **рабочего** скриншота сайт показывается как цветная плитка, в духе классического Opera Speed Dial: **однотонный насыщенный фон, крупный hostname в одну строку по центру**. Это новая функция существующего WXT-приложения, не миграция. Не меняй структуру закладок, категорий, кэширования, механизм захвата или настройки.

### Требования к поведению

1. **Режим `thumbnail`:** изображение валидно и декодируется — оставь нынешнюю плитку 16:9, скриншот во весь фон, нижнюю светлую полоску с favicon и заголовком, прежний hover. При повреждённом или недекодируемом Blob автоматически переходи в `text`.
2. **Режим `text`:** `thumbnail` отсутствует, недекодируем, захват не удался или локальный кэш ещё пуст — показывай цветной фон и единственную крупную надпись **hostname из URL**. **Не отображай нижнюю полоску, favicon или отдельную букву-заглушку.** Наличие favicon не определяет режим.
3. **Текст:** из `new URL(bookmark.url).hostname`, привести к нижнему регистру, убрать начальное `www.` для отображения. Протокол, путь, query/fragment не показывать. Если hostname недоступен — безопасная заглушка `Сайт`. Пользовательский `bookmark.title` не изменять и не использовать вместо hostname в текстовом режиме; полный заголовок и адрес остаются в доступной подписи/tooltip ссылки.
4. **Размер надписи:** только **одна строка**, никаких переносов на 2–3 строки. Бери максимально крупный доступный размер шрифта, который умещается по фактической ширине карточки с внутренними отступами. Используй измерение текста (`canvas.measureText()` либо проверку реального DOM-элемента) + бинарный поиск подходящего font-size, и `ResizeObserver` для изменения размеров карточки. Не завязывай расчёт лишь на `window.innerWidth`.
5. **Минимальный размер:** не уменьшай шрифт до нечитаемости. При крайне длинном hostname или очень узкой плитке показывай одну строку с `…`, сохраняя максимально узнаваемую часть (обычно начало hostname и при возможности доменную зону). Не выходи за карточку; `min-width:0`, `overflow:hidden`, `white-space:nowrap`, аккуратный `text-overflow` или вычисленное усечение.
6. Пересчитывай размер при изменении URL, ширины сетки, количества столбцов, размеров окна, подключении шрифтов. Избегай измерения до готовности размеров и бесконечных циклов `ResizeObserver`/layout thrashing; очищай observer при размонтировании. Реализуй устойчивость к SSR-неиспользуемым DOM API в unit-тестах.
7. **Цвет:** зафиксированная локальная палитра 8–12 насыщенных оттенков с контрастом надписи по WCAG AA не ниже 4.5:1. Детерминированный хеш **нормализованного hostname** → индекс палитры; `www.example.com` и `example.com` получают одинаковый цвет. Переименование/сортировка/категория/favicon/id не влияют. При смене домена цвет может измениться. Не сохраняй `tileColor`, `tileMode` в DB/Bookmarks/Storage/JSON.
8. Сохрани текущую геометрию 16:9, радиус, тени, фокус, drag-state, текущий акцент (до F05 жёлтый, после F05 настраиваемый), существующую кнопку добавления. Все карточки — смешанные текстовые и со скриншотами — одинакового размера. `+` и заголовки категорий не являются текстовыми плитками.
9. Новые/синхронизированные закладки без локальных эскизов открываются и показываются **мгновенно**, без ожидания favicon/скриншота. Корректный снимок появляется → автоматически включается `thumbnail`. Ошибка захвата → прежняя текстовая плитка; ошибка обновления уже имеющегося правильного скриншота не уничтожает этот скриншот.
10. Обрабатывай `Blob` и `blob:` URL без утечек/гонок; можно заменить CSS `background-image` на `<img>` с проверкой `load/error/decode`, если это не ломает существующий вид. При смене URL не показывать старый эскиз (`[bookmarkId+url]`). Не добавлять фоновых сетевых запросов для этой функции.
11. Плитка остаётся настоящей ссылкой: click/Enter открывает URL; контекстные меню, удаление/редактирование/обновление эскиза, DnD и внешние события Bookmarks API работают как прежде. Вывод строки через безопасную Vue-интерполяцию.
12. Учитывай reduced motion, фокус клавиатуры, высокую контрастность и чёткость русского интерфейса; **никакого общего редизайна**.

### Где работать

Основные: `components/BookmarkGrid.vue`, новый небольшой `utils/tile.ts` (чистые нормализация/цвет/подбор), при необходимости компактный composable для ResizeObserver. ## F02 · P1 · Выполнена · Выбор папки закладок непосредственно в настройках

**Выполнена 17 октября 2026.** Выбор источника перенесён в настройки; старое окно выбора и массовая очистка удалены. По уточнению пользователя убраны пустой пункт «Выберите папку» и поясняющий текст под селектом. Ниже сохранены требования и сценарии для регрессионных проверок.

### Цель, интерфейс и границы

**Совместимость с F05:** описанные ниже кнопка «Сохранить», черновик выбора папки и связанные тесты фиксируют **историческое поведение выполненной F02**. После F05 оно **заменяется немедленным переключением источника по select и автосохранением без кнопки**; все требования F02 по безопасности, структуре папок, выбору по умолчанию и отсутствию мутаций Bookmarks API остаются обязательными. При проверке актуального продукта приоритет имеет F05.

**Исходная цель F02 (уже выполнена).** Полностью отказаться от старого UX выбора основной папки через отдельное `FolderDialog.vue` и предложения создать папку с именем `Speed Dial`. Вместо него в существующей панели `Настройки` добавить **одно поле `<select>` с подписью `Папка закладок`**. Выбранная папка является **только источником отображения** плиток и категорий. На **чистой установке / в новом браузерном профиле** автоматически использовать системную **«Другие закладки»** (`Other bookmarks`); *пользователь может затем выбрать любую доступную папку из дерева браузера*. **Выбор и смена папки не создают, не удаляют, не очищают, не перемещают и не переименовывают закладки или папки. В рамках F02 не вводи никакого механизма удаления. Убери прежнюю кнопку массовой очистки папки целиком**, а не только для системной папки. Не менять Bookmarks API как источник данных, существующую сетку, плитки F01, изображения, настройки визуального вида или другие функции.

**Подтверждённые источники браузерного API (прочитать при реализации):**
- Chrome Bookmarks: https://developer.chrome.com/docs/extensions/reference/api/bookmarks — свойство `folderType: 'other'` (Chrome 134+), `syncing`, `unmodifiable`, `getTree()`. `folderType` у системной папки означает, что нельзя **изменить саму папку**, но можно **работать с её дочерними элементами**, если она не `unmodifiable`.
- Несколько деревьев в Chrome (аккаунтные и локальные корни): https://developer.chrome.com/blog/bookmarks-sync-changes — в дереве может быть **несколько `folderType: 'other'`**. Нельзя полагаться на уникальное название, фиксированный числовой ID или наличие только одного стандартного корня.
- Firefox: https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/bookmarks/getTree и https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/bookmarks/getChildren — другая структура/свойства; у «Других закладок» обычно есть ID `unfiled_____`, но **не используй Firefox GUID как универсальное правило для Chrome**, проверь доступный дерево/тип в реальном Firefox.

### Точный UI-контракт

1. В `components/SettingsPanel.vue` создать обычную строку настроек, например:

   `Папка закладок: [ Другие закладки                                 ▾ ]`

   Использовать **нативный доступный `select`** с `<label for=...>` (или label-обёрткой), в стилистике текущих полей. Не добавлять новый modal, wizard, popup/поисковый select с тяжёлой библиотекой. Желательно разместить в верхней части настроек, **до** ширины/колонок/отступов, в логичном месте рядом с подсказкой о синхронизации. Существующую строку/кнопку `Выбрать основную папку` убрать.
2. В списке должны быть **все доступные папки пользовательского дерева** (в том числе вложенные папки любого уровня, пользовательские папки `Speed Dial`, стандартные «Панель закладок», «Другие закладки», «Мобильные закладки», их локальные/аккаунтные варианты, если присутствуют и позволяют работать с дочерними элементами). **Не** предлагать URL-закладки, технический корень всего дерева, разделы управляемых закладок/защищённые от записей ветви. Недоступные папки — либо вообще не показывать, либо показывать как `disabled` с понятной причиной; **выбрать их невозможно**.
3. Плоский `<select>` должен оставаться понятным при одинаковых названиях: отображай **полный путь** из цепочки родителей (например, `Другие закладки / Работа / Проекты`), а при наличии свойств Chrome — различай одинаковые системные расположения метками `(аккаунт)`/`(локально)`. Отступы в названиях могут помогать, но **не заменяют путь**. Сохраняй реальные пользовательские названия без переименования в дереве. Не используй `title` или строку пути в качестве ID значения `<option>`: `:value` — строковый ID `BookmarkTreeNode.id`.
4. Порядок опций: естественный обход дерева от системных папок к их дочерним в текущем порядке Bookmarks API. Не меняй реальный порядок дерева ради красивого списка; поддержи сотни/тысячи папок без заморозки страницы, без сетевых запросов. На узком экране длинный путь можно сокращать в визуальной части, но полный путь должен быть доступен (`title`/доступная подпись). Без горизонтального переполнения всей панели.
5. Папки загружаются из `browser.bookmarks.getTree()` при открытии настроек, с понятным состоянием загрузки и ошибки. При внешнем изменении дерева (`onCreated`, `onRemoved`, `onChanged`, `onMoved`, `onChildrenReordered`, `onImportEnded`) список актуализируется, пока настройки открыты; обновление не должно молча менять сделанный пользователем, но ещё не сохранённый выбор. Никаких сетевых запросов и второго каталога папок в Dexie.
6. **Применение через существующую кнопку `Сохранить`** вместе с прочими настройками. Просто раскрыть селект или выбрать в нём другое значение **не переключает** плитки и не пишет в Bookmarks. Если панель закрыть без сохранения, прежний корень остаётся активным. При невалидном ID или отказе API оставить панель открытой с ошибкой, не показывать «сохранено» и не терять прежний корень. Если настройки/корень требуют двух асинхронных вызовов, тщательно обработай частичный отказ, чтобы UI не расходился с сохранённым состоянием.
7. После успешного сохранения **сразу** показывай прямые ссылки/папки выбранного корня без перезагрузки браузера; активную категорию безопасно переключай на «Главную» / допустимый первый раздел по действующему UX. Переименование папки не должно терять выбор, если ID тот же. Изменённый корень должен отражаться и в других уже открытых экземплярах SpeedDial X через существующий механизм `rootItem.watch`/`BroadcastChannel`; исключить гонки устаревших `load()`.
8. Над полем или под ним — короткая подсказка: `Закладки и категории будут отображаться из выбранной папки. Переключение ничего не переносит и не удаляет.` Никаких дополнительных кнопок создания, очистки или удаления папок рядом с селектом. Существующие операции над **отдельными** плитками и категориями являются другим функционалом приложения и не запускаются при выборе папки.

### Выбор по умолчанию, совместимость и состояния

9. **Первый запуск, нет сохранённого `local:rootFolderId`:** сначала `getTree()`, определить корректную системную папку «Другие закладки» и **сохранить её реальный ID** в уже существующем `rootFolderId` (не создавать никакую папку). Для Chrome 134+ использовать `folderType === 'other'`, а не `title === 'Другие закладки'`, английское название или магическое `'2'`. Для Firefox проверить соответствующий `unfiled` корень в его модели; предусмотреть безопасную совместимость с реализацией без Chrome `folderType`. Для других браузерных вариантов допускается строгий детектор после проверки дерева, но никогда не выбирай произвольную пользовательскую папку по совпадению названия `Other`.
10. **Если несколько `folderType:'other'`:** если ровно один однозначно помечен `syncing:true` и пригоден для редактирования содержимого — предпочесть его, иначе при возможности выбрать единственный доступный корректный вариант; если осталась **неустранимая неоднозначность**, не выбирай «первый попавшийся» и не переносить данные: покажи понятное сообщение `Выберите папку закладок в настройках`. При этом все кандидаты должны быть видны в селекте с различиями `аккаунт`/`локально`. Выбор аккаунтного дерева **не доказывает** включение или завершение Chrome Sync.
11. **Существующие пользователи:** если `local:rootFolderId` уже хранит ID корректной доступной папки `Speed Dial` (или иной пользовательской папки), **сохрани этот выбор** после обновления и не перебрасывай на «Другие закладки». Вопреки названию папки, поле должно показывать выбранный путь; имя папки теперь не является специальным контрактом приложения. Не запускать старый поиск `Speed Dial` по названию и не создавать её автоматически. Старую папку `Speed Dial` не удалять, не переименовывать и не переносить из неё данные.
12. **Сохранённый ID удалён, недоступен или папка перемещена в управляемую ветвь:** не считать это поводом для массовых операций или создания дублей. Перепроверить дерево; когда остаётся единственный безопасный дефолт — выбрать `Другие закладки`, показать короткое уведомление о переключении. Если нельзя однозначно выбрать дефолт — оставить `rootId=null` и встроенное сообщение со ссылкой на настройки; **без старого диалога выбора**. Переименование/перемещение папки с сохранением ID не должны менять источник сами собой.
13. **API отсутствует / permission denied / дерево недоступно:** не создавать данные, не прятать ошибку за пустым списком, не зацикливать автоматический выбор. В настройках — понятный текст об отсутствии доступа; на новой вкладке — inline уведомление/кнопка `Открыть настройки`, а не `FolderDialog`. Если выбранная папка пуста, нормальная пустая сетка с действующей возможностью добавить закладку (кнопка `+`, контекстное меню и т.п.).
14. **Выбран системный `folderType` (например `other`):** отличай **защиту системной папки** (нельзя переименовать/переместить/удалить её саму) от возможности использовать её как источник плиток и категорий. Исправь `folder()`, `selectable()`, `folderChoices()`, `Repository.selectRoot()`, `initialize()`, `load()`, `rootNode()` и связанные проверки так, чтобы встроенная «Другие закладки» действительно могла быть корнем, а браузерный технический корень/managed-ветви не могли. **Сам выбор папки не вызывает `browser.bookmarks.create/update/move/remove/removeTree`**. Существующий CRUD **отдельных** плиток и категорий должен продолжать работать по явному действию пользователя и только в допустимой выбранной ветви; он не является частью операции смены папки.
15. **Смена выбранной папки — исключительно операция выбора:** разрешены чтение Bookmarks API, проверка доступа к дереву и обновление `local:rootFolderId` (а также сохранение других полей формы, только если их явно изменил пользователь). **Никаких мутаций дерева:** не вызывать `bookmarks.create`, `bookmarks.update`, `bookmarks.move`, `bookmarks.remove`, `bookmarks.removeTree`; не копировать, не менять порядок, не переименовывать и не очищать папки. Не очищать Blob-кэш, не сбрасывать фон и другие настройки. При A → B → A прежние закладки и изображения A должны отобразиться снова; кэш привязан к `[bookmarkId+url]`. `rootFolderId` — локальная настройка профиля, а не часть переносимого JSON или синхронизируемых закладок.
16. **Убрать массовое удаление из настроек для ВСЕХ папок.** Полностью удалить кнопку `Очистить выбранную папку` из `SettingsPanel.vue` независимо от того, системная папка выбрана или пользовательская. Удалить связанный обработчик `clearFolder` и событие `clear` из `App.vue`/`SettingsPanel.vue`. Удалить неиспользуемую публичную операцию `Repository.clear()` (или сделать её недоступной, если есть другие реальные вызовы; не оставлять обходного пути массового удаления). **Не заменять кнопку другой командой очистки**, даже с подтверждением. Сохранить отдельную существующую функцию `Сбросить настройки и кэш`: она затрагивает только настройки/локальные изображения, но **никогда не удаляет настоящие закладки и не сбрасывает `rootFolderId`**. Существующее удаление **одной** плитки или явно выбранной категории в их собственных меню не расширять и не запускать при выборе папки; защитные подтверждения и проверки этих независимых операций не ослаблять.
17. **Категории после выбора:** «Главная» по текущей модели — это **не отдельная папка**, а прямые закладки текущего выбранного корня, даже если корень «Другие закладки». Реальные прямые дочерние папки становятся категориями; глубокие папки по-прежнему не отображать и не трогать. Не реализуй здесь новый постоянный UX «Главной» и `+` — это отдельная F09. Действующая сортировка и перенос закладок через `BookmarkDialog` должны писать только внутрь выбранной папки/её прямых категорий.
18. **Совместимость импорта/экспорта:** импорт пишет только в **текущий выбранный корень** после явного подтверждения и прежней валидации. Экспорт берёт данные только из выбранного корня и прямых категорий, без чужих ветвей. Не включай ID выбранной папки в переносимый JSON и не внедряй F12 (формат JSON v3). Перед импортом стоит явно указывать название выбранной папки в подтверждении, чтобы пользователь понимал, куда попадут реальные закладки. Нельзя молча очистить содержимое выбранной папки.
19. **Firefox и другие профили:** в Firefox учитывать отдельные корневые категории Bookmarks и возможность отсутствия Chrome `folderType`/`syncing`; в Chrome учитывать дубли системных папок в локальном/аккаунтном дереве. При запуске в другом профиле со своим Storage использовать собственный дефолт и не предполагать, что bookmark ID совпадает между профилями. Весь путь и подсказки в UI — на русском, даже если системные имена браузера локализованы иначе (собственные названия папок не менять).

## F03 · P1 · Выполнена · Поиск по собственным закладкам

**Выполнена 17 октября 2026 с уточнениями пользователя, имеющими приоритет над исходными требованиями.** Поиск начинает фильтрацию при вводе; кнопка с лупой справа, поле занимает 30% ширины окна на компьютере и всю доступную ширину на мобильном. При поиске категории скрыты с сохранением геометрии; крестик расположен внутри поля. Внешний клик закрывает поиск, а клик по плитке сохраняет выдачу до перехода. Дополнительных подписей на плитках нет. Блок отсутствия результатов появляется после паузы 400 мс. Настройка видимости включена по умолчанию; отключает также `/`. Отчёт о проверках — `docs/verification.md`.

### Цель

Дать возможность быстро найти плитку **во всех категориях выбранной папки**, не путать этот поиск с отправкой запроса в Яндекс/Google. Сейчас `SearchBar.vue` ищет только в интернете; в `App.vue` нет поиска по Bookmarks API.

### Требования

1. Рядом с панелью категорий размести **компактную кнопку с иконкой лупы**, понятным tooltip/aria-label `Поиск по закладкам`. Не создавай вторую большую строку поиска при закрытом режиме.
2. Нажатие раскрывает компактное поле локального поиска. В пустом состоянии показывай обычную выбранную категорию. Символ `/` при отсутствии фокуса в input/textarea/contenteditable/диалоговом окне открывает локальный поиск и переводит фокус в поле, не вводя сам `/` в запрос. Никаких пересечений с вводом в основной интернет-поиск.
3. Ищи по **названиям и URL**, регистронезависимо; trim пробелов; не надо делать fuzzy API или сетевые запросы. Результаты охватывают прямые закладки корневой папки «Главная» и непосредственные закладки прямых дочерних категорий. **Более глубокие скрытые папки не показывать и не изменять.**
4. Показывай результаты с названием сайта и категорией (например, `Работа`/`Главная`); сохраняй доступность клика, контекстного меню, favicon/эскиза/текстового режима F01. Поиск — временный view, не новая категория, не перемещение, не изменение порядка.
5. Не загружай вторую локальную базу. Читай дерево через текущий Bookmarks API/repository, корректно реагируй на внешние изменения/синхронизацию. Если результат исчез или сменил URL при открытом поиске, не показывай неактуальную плитку/изображение.
6. При поиске не позволяй перетаскиванием записать случайный порядок между разными категориями. Уведомляй об отсутствии результатов и ошибке чтения. Закрытие поиска/Escape возвращает прежний вид и активную категорию. Очистка строки — все результаты либо нормальный вид по текущему UX, но **поведение единообразное и протестированное**.
7. При пустой выбранной папке показывай штатный empty state; при недоступном корне — встроенную подсказку «Настройки → Папка закладок» (без старого FolderDialog), а не ошибки. UI не перекрывает `+`, поиск по интернету и почту.

**Файлы:** `App.vue`, `components/SearchBar.vue` (сохранить интернет-поиск), `components/BookmarkGrid.vue`, при необходимости `components/BookmarkSearch.vue`, `composables/useDial.ts`, `services/repository.ts`. Новый поиск должен быть отдельной логикой от `services/network.ts`.

### Приёмка / тесты F03

- `T01`: три категории, совпадение в корне и обеих папках → видны все соответствующие закладки, метки источника корректны.
- `T02`: поиск по фрагменту URL, заголовку, разному регистру, пробелам → предсказуемая фильтрация.
- `T03`: deep folder → результат не показывается.
- `T04`: `/` на пустой странице фокусирует локальный поиск; `/` внутри интернет-поиска и диалога остаётся обычным символом.

**Готово:** можно найти закладку из любой отображаемой категории, не включая интернет-поиск. Один коммит, после него остановись.

## F04 · P1 · Выполнена · Мультипоиск с обязательными подсказками во всех пяти сервисах

### Цель и обязательный результат

Превратить основную строку поиска в **единый мультипоиск**: **Яндекс, Google, Кинопоиск, IMDb, MyShows**. Источник выбирается **не в настройках**, а **непосредственно слева в строке поиска**. Существующие подсказки Яндекса сохранить; у **каждого из остальных четырёх** источников должны появиться **реальные подсказки во время ввода**, связанные именно с выбранным сервисом. **Наличие кликабельной поисковой ссылки без работающих подсказок НЕ является завершённой F04.** Bing и DuckDuckGo **не добавлять** в этой функции.

В кино-сервисах подсказки предпочтительно показывают **конкретные найденные фильмы/сериалы (а в IMDb также людей)** с названием, годом при наличии и целевым URL соответствующего сайта. Это отличается от текстовых продолжений поискового запроса у Яндекса и Google. Не смешивать мультипоиск с F03 — локальным поиском по закладкам у категорий.

### Интерфейс: один селект внутри строки поиска

1. Слева от текстового поля разместить **компактный нативный `<select>`** с доступным именем **`Где искать`**. В выбранном состоянии показывать **полное название сервиса**, а не одну иконку. Список должен быть **плоским, без групп, заголовков, разделителей и `<optgroup>`**: ровно пять пунктов с названиями `Яндекс`, `Google`, `Кинопоиск`, `IMDb`, `MyShows` в указанном порядке. Не добавлять ряд из пяти иконок и вторую поисковую строку.
2. **По умолчанию Яндекс**, как сейчас. Выбранный вариант сохранять между новыми вкладками и перезапусками браузера в текущем WXT Storage; неизвестное/устаревшее значение восстанавливать как Яндекс. **Отдельный пункт `Поисковая система` в SettingsPanel.vue не создавать**: место переключения — сама строка.
3. Сохранять прежние размеры/стиль главного поиска насколько это возможно: единая визуальная группа `[select] [поле] [кнопка Найти]`, скругления по внешним краям, фирменный акцент выбранной поисковой системы, текущие высота и вертикальные отступы. При 360px поле и селект не должны перекрывать друг друга; `min-width: 0`, разумное сокращение ширины селекта при необходимости, без горизонтальной прокрутки страницы. По умолчанию русский интерфейс и существующая доступность.
4. Смена источника **не очищает введённый текст**, но закрывает старые подсказки, отменяет их запрос и запускает запрос нового провайдера (если текст непустой). Placeholder может показывать `Поиск в Google…`, `Поиск в IMDb…` и т.д. Кнопка и Enter для введённого запроса используют только выбранный сервис.
5. Локальный поиск закладок F03 (`/`, кнопка-лупа у категорий), Mail.ru, категории и эскизы не затрагивать. Ключ `/` не должен перехватываться внутри основного поля или селекта.

### Архитектура и безопасность

6. Для пяти сервисов определить общую типизированную модель `SearchProviderId` и `SearchSuggestion`, например: `{ id: string; label: string; subtitle?: string; targetUrl?: string }`, и адаптеры `searchUrl(query)` / `suggest(query, signal)`. **Не** делать пять независимых копий компонента. Текстовые подсказки имеют только `label`, киноподсказки могут иметь `targetUrl` на конкретный фильм/сериал/персону. Парсеры держать отдельными чистыми функциями и тестировать на сохранённых фикстурах реальных ответов.
7. **Для кино-сервисов обязательно реальные результаты каталога выбранного сайта**. Нельзя подменять MyShows Google `site:myshows.me`, Кинопоиск Яндексом, IMDb Google или предлагать синтетические варианты «{query} фильм/сериал» под видом найденных карточек. Не использовать историю браузера, закладки пользователя, IMDb/TVMaze/TMDB как скрытую замену выбранной площадки. Если разрешённый независимый источник будет отдельно согласован пользователем, это требует отдельного решения и честной маркировки.
8. **Порядок действий при кино-сервисе:** в настоящих браузерных инструментах исследовать сетевые запросы при вводе на самом официальном сайте; найти endpoint и схему, проверить доступность из extension context, необходимость host permission/CORS, авторизацию, лимиты, возможный CAPTCHA/anti-bot и правила использования. **Не** пытаться обойти защиту подделкой сессий, краденными cookies, `Origin`/`Referer`, инъекцией скриптов на чужой сайт, невидимым открытием вкладок или собственным прокси. Не включать в расширение секретные API-ключи/OAuth без отдельного согласования. Если существующий источник нестабилен, явно описать ограничение, а не выдавать моки за доказательство.
9. Сетевые запросы для получения подсказок должны идти **только к выбранному провайдеру или его документированному/проверенному домену подсказок**. Не отправлять введённую строку параллельно всем пяти сервисам, не сохранять историю пользовательских запросов, не передавать cookies или чувствительные заголовки, если сервис реально не требует их и это не согласовано. Кроссдоменные запросы выполнять в корректном extension-контексте. Проверять, какие `host_permissions` уже есть; новые — только при доказанной необходимости.
10. Для запросов использовать debounce около **250 мс**, `AbortController`, общий `generation/requestId` и тайм-аут; при смене текста/провайдера или размонтировании отменять устаревшее. Пустой запрос не отправлять; ограничить объём ответов и количество результатов, обычно максимум **6–10 элементов**. Старый запрос Google не должен попадать в подсказки MyShows после переключения.
11. Строго проверять `Content-Type`, HTTP status, JSON-формат, массивы/объекты, поля ID/URL, длину текста и допустимые домены ссылок. **Никакого `eval`, JSONP, `v-html` или вставки HTML страницы ответа**. Для IMDb `tt…` и `nm…` использовать только корректные ID и URL `https://www.imdb.com/…`; для остальных также принимать только проверенную навигацию на официальном домене соответствующего провайдера. Рендер Vue-интерполяцией; не доверять серверу в вопросе прямой ссылки.
12. **Единое управление:** ArrowDown/ArrowUp меняют выделение, Enter по выбранному пункту открывает именно его `targetUrl` (когда есть) или выполняет текстовый поиск; Enter без выбранного пункта и кнопка `Найти` всегда открывают страницу поиска по исходному вводу. Клик по кино-подсказке — **прямо на выбранную карточку** соответствующего сайта; клик по текстовой подсказке — на выдачу выбранного поисковика с её текстом. Escape закрывает список, клик вне — как в существующем Яндексе. Выделение не должно навсегда подменять введённый запрос.
13. Результаты кино-сервиса показывать текстовыми строками (без обязательных постеров): **`Название (год)`** либо `Название · сериал/фильм/человек`, когда эти сведения реально пришли. Никаких выдуманных годов/типов; длинные имена сокращать визуально с доступным полным текстом. Не вводить тяжёлые библиотеки, виртуализацию и сложные новые модалки.
14. При пустом ответе — спокойное пустое состояние; при сетевой ошибке/403/429/CORS/устаревшем endpoint — `Подсказки временно недоступны`, **основной поиск остаётся рабочим**. Это необходимая безопасная деградация во время сбоя, **а не разрешение выпустить F04 с постоянно отсутствующими подсказками** у одного или нескольких источников. Если хотя бы один провайдер невозможно подключить надёжно и корректно, **статус F04 — частично выполнена/блокирована, а не «готово»**. Зафиксировать причину и предложить отдельное решение, но не начинать F05 и не удалять требование подсказок по своей инициативе.
15. Сохранять настройки выбранного провайдера в существующем WXT Storage и совместимость с текущим `Settings`, `validateSettings`, импортом/экспортом JSON v2; не менять версию формата просто из-за нового поля. Переход на JSON v3 — отдельная F12. Текущий поиск Яндекса и локальный поиск F03 должны остаться функционально прежними.

### 2. Переключение категорий и папок без мерцания фона

10. **Исправить визуальный скачок при выборе категории («папки с плитками»)**, а также при изменении папки-источника в настройках: смена содержимого сетки должна происходить **без перезагрузки документа, исчезновения или краткого сброса фона, мигания шапки и всего layout**. Смена категории меняет активное выделение и список плиток, не пересоздавая приложение. Не добавлять искусственный fade всей страницы или глобальный loading-overlay, маскирующий мерцание.
11. **Диагностика по текущему коду (гипотеза, проверить):** `useDial.refresh()` заново загружает весь `Snapshot`, включая `background` из IndexedDB; `App.vue` при изменении ссылки на `Blob` отзывает прежний `blob:` URL и создаёт новый. Даже при **неизменном содержимом** фона новый объект `Blob` может приводить к повторному созданию URL и визуальному мерцанию. Проверить это в браузере; не считать гипотезу установленным фактом без воспроизведения. **Отвязать жизненный цикл фонового изображения от загрузки текущих плиток**: фоновый URL должен оставаться стабильным до фактической замены/удаления фона (можно отдельно хранить загруженный ресурс или эквивалентно исключить лишние обновления). При замене не отзывать прежний ресурс до применения нового; освобождать Blob URLs при реальном изменении и размонтировании.
12. Быстрая последовательность **А→Б→А** для категорий и источников не должна возвращать поздний ответ для устаревшего выбора. Сохранять корректное активное выделение и показывать плитки только для подтверждённой текущей категории/источника; защищаться от гонок и удалённых извне папок. Не очищать `snapshot` или сетку до получения новых данных без необходимости, не показывать устаревшие плитки как новые. Отсутствие плиток в действительно пустой категории — нормальное пустое состояние, а не мигание. Никаких записей в Bookmarks API при обычном переключении.
13. На пользовательском фоне и стандартной заливке проверить отсутствие скачков при переходе между категориями, открытии/закрытии настроек и смене папки-источника. Не делать ненужных повторных чтений изображения при обновлениях favicon, закладок или контента. Стабильность `background-image`/`blob:` URL проверить автоматически (шпионы на `URL.createObjectURL`/`revokeObjectURL`, симуляция разных экземпляров Blob) и визуально в реальных Chrome/Firefox с изображением. Исправление не должно ухудшать локальный поиск F03, DnD и отображение кешированных эскизов.

Корректный ввод в контролах применять визуально сразу, сохранять через единый механизм F05; числовые параметры задавать единообразными полями ввода с указанием единиц и пределов; debounce, по `blur/change` — отправка последнего валидного значения.

Во встроенной поисковой строке скруглить только наружные углы, не внутренние стыки; круглая форма статусных значков не нарушается. Screenshot не выступает за закруглённую плитку.

Настроенное значение не должно делать элементы полностью невидимыми.

В обычном состоянии не размывать сами скриншоты, текст или всю страницу; при открытых настройках размывать фон и основное содержимое с переходом 250 мс, если uiBlur включён; избегать множества вложенных backdrop-filter на кнопках внутри уже размытой панели. Проверить fallback без `backdrop-filter`, производительность и `prefers-reduced-motion`.

Выбранный `uiAccent` используется для активной категории, чекбоксов/радиокнопок, акцентных действий, DnD-выделения, релевантных hover/active/focus. Не менять фирменные цвета пяти провайдеров F04, цветные плитки F01, favicon, скриншоты, красный и зелёный статусы синхронизации, ошибки и опасные действия. Контрастный цвет текста/иконок на насыщенном акцентном фоне вычислять автоматически для экстремально светлого/тёмного цвета.

### 2. Цельная визуальная система

7. Создать согласованные семантические CSS-токены: радиус, альфа поверхности, blur, акцент, мягкий акцентный оттенок, контраст акцента, несколько уровней фонов/рамок/теней. Допустимые названия: `--ui-radius`, `--ui-surface-alpha`, `--ui-blur`, `--ui-accent`, `--ui-accent-soft`, `--ui-accent-contrast` и другие только по необходимости. Заменить разрозненные `rounded-[5px]`, `bg-white/80`, `backdrop-blur-[10px]`, `#FFCC00`, `#FFEBA0` **на поверхностях интерфейса**, не ломая специальные стили содержимого.
8. **Glassmorphism — стиль, не отдельный режим или опция.** Полупрозрачные нейтральные поверхности, умеренный управляемый blur, тонкие границы и мягкие тени создают единый язык. При прозрачности `0%` или выключенном blur интерфейс всё равно должен быть цельным, хорошо читаемым и не требовать пользовательской фоновой фотографии. Без декоративных бликов, дополнительных вложенных стеклянных панелей и тяжёлых эффектов.
9. **Контраст на разных фонах:** проверить белые, тёмные, пёстрые изображения, фон по умолчанию, прозрачность 0/20/50% при blur on/off. Цель для обычного текста — WCAG AA 4.5:1, обычные рамки и клавиатурное выделение по согласованию с пользователем сделать мягкими, без контрастной чёрной обводки; системный forced-colors сохраняет контрастный фокус. Само размытие не гарантирует контраст; использовать ограниченные локальные подложки, границы, тени и адаптивные текстовые цвета по необходимости, не подменяя пользовательский выбор прозрачности. Статусы различимы не только цветом.
10. **Единая шкала отступов** 4, 8, 12, 16, 24, 32 px; последовательно применять её к группам настроек, формам, диалогам, панелям, категориям, меню, подсказкам. Сохранять разумную компактность без лишней вложенности карточек. **Типографика:** согласовать размеры/насыщенность заголовков, подписей, пояснений, меню; line-height и длинные русские названия. **Тени/границы:** немного семантических уровней глубины вместо тяжёлой тени на каждой плитке.

## F07 · P1 · Синхронизация настроек и выбранной папки через Chrome Sync

**Статус · 19.10.2026: реализована.** Коммит создаётся пользователем. Автоматические проверки и ограничения — [verification.md](verification.md). Доставка между реальными Google-аккаунтами/компьютерами и ручное переключение аккаунтов не подтверждены автоматическими фикстурами.

### Цель и границы

Реализовать автоматическую **синхронизацию небольших пользовательских настроек и переносимого описания выбранной папки закладок SpeedDial X между браузерами Chrome одного аккаунта** с помощью нативного `chrome.storage.sync` / WXT `sync:`. **На этапе разработки расширение устанавливается вручную как распакованное (Developer Mode), без публикации в Chrome Web Store; стабильный ID расширения на разных компьютерах — часть обязательной приёмки F07.** Нового сервера, входа в Google из расширения, собственных OAuth-токенов и пользовательского переключателя «синхронизация SpeedDial X» не требуется. При выключенном Chrome Sync настройки продолжают храниться и работать локально, а при восстановлении Chrome Sync браузер может перенести их на другие устройства при поддерживаемой синхронизации расширений. Существующие F05 (автосохранение) и F06 (оформление) должны работать без изменений с точки зрения пользователя. Chrome Sync сохраняет **описание выбора папки** отдельно от собственно закладок, которые Chrome синхронизирует своим механизмом. Старые ограничения F02 на отсутствие отдельной синхронизации относятся к этапу до F07: с F07 переносится только локатор папки, а реальный `rootFolderId` по-прежнему локален и деревом управляет только Bookmarks API.

**Важно:** `chrome.identity.getProfileUserInfo({ accountStatus: 'SYNC' })` показывает общий статус синхронизации профиля и, если доступно, email; он **не** сообщает, включена ли отдельно синхронизация расширений, произошла ли доставка данных на другое устройство и не предоставляет имя/фамилию. Не смешивать статус профиля Chrome с успехом локальной записи в `storage.sync` или фактом облачной доставки. При недоступном/неизвестном статусе сохранять нейтральный интерфейс и работоспособные настройки.

### 1. Что синхронизировать

1. Синхронизировать **все существующие значения `Settings`**, а также будущие не чувствительные скалярные пользовательские параметры по мере их добавления: ширину сетки, количество столбцов, отступы, центрирование, плитку `+`, локальный поиск, выбранный поисковик, email Mail.ru как пользовательскую настройку, `uiRadius`, `uiTransparency`, `uiBlur`, `uiAccent`. После F11/F13/F14 новые параметры темы, виджета погоды и почты должны использовать тот же механизм автоматически и проходить соответствующую валидацию. Перед синхронизацией отправлять только явно разрешённые ключи схемы `Settings`, без неизвестных дополнительных полей.
2. **Синхронизировать выбор основной папки, но не её ID.** Помимо разрешённых полей `Settings` хранить в отдельном ключе `storage.sync` небольшой версионированный *переносимый локатор выбранной папки*: тип стандартной родительской ветви, признак аккаунтного/локального хранения `syncing` (если доступен) и последовательность настоящих названий дочерних папок. Локальный `rootFolderId` остаётся в `storage.local` и на каждом устройстве вычисляется заново через Bookmarks API. **Активную категорию `activeId` не синхронизировать**. Не включать в `storage.sync` ID закладок/папок, дерево закладок, названия/URL отдельных плиток, их порядок, настройки Google-аккаунта, Google email/ID из `identity`, фон, Blob/data URL, Base64, favicon, скриншоты, индексы Dexie или временные состояния UI. Локатор папки — не перенос списка её закладок.
3. **Закладки и категории** остаются в `browser.bookmarks` и синхронизируются Chrome самостоятельно при соответствующей настройке браузера. Синхронизация локатора выбранной папки сама по себе **не** переносит содержимое папки. **Пользовательский фон, эскизы и favicon** остаются локальными в IndexedDB. Полный перенос через JSON (включая изображения) остаётся отдельной F12; при импорте настройки применяются и попадают в текущий механизм sync, а изображения — только в локальный кэш. Не вводить вторую базу URL закладок или дополнительную сеть.

### 2. Хранение, миграция и конфликты

4. Использовать имеющееся разрешение `storage` и WXT Storage / `browser.storage.sync`. Квоты Chrome: **102400 байт на расширение, 8192 байта на ключ, 512 ключей, 120 операций записи в минуту и 1800 в час**. Настроек и локатора папки мало, но не писать при каждом символе или каждом кадре выбора цвета: сохранять немедленное визуальное preview из F05/F06, а записи в `sync` объединять по изменённым полям с задержкой/ограничением частоты, с принудительным flush на `change`/`blur`/закрытии панели. Проверять реальные ошибки quota/API. Не рассчитывать на `unlimitedStorage` как способ увеличить лимит `sync`.
5. Для конкурентных правок **разных параметров** избегать перезаписи всего устаревшего объекта `Settings` на другом устройстве. Предпочтителен типизированный per-field формат ключей в `sync` (либо эквивалент с подтверждённой изоляцией изменений), с единым списком разрешённых полей, валидацией и централизованным адаптером. Одновременно несколько изменённых полей можно передавать одним вызовом `storage.sync.set()` в пределах квот. Синхронизация **одного и того же поля** между офлайн/параллельными устройствами может завершаться выбором последней доставленной записи средствами браузера; не обещать распределённых транзакций, точной последовательности доставки или разрешения конфликтов, которых API не даёт.
6. **Миграция без потери существующих настроек:** до F07 настройки находятся в `local:settings`. На каждом устройстве корректно объединять сохранённые локальные пользовательские параметры с уже существующими допустимыми записями `sync`; переносимый локатор папки мигрировать из подтверждённого локального `rootFolderId` через чтение дерева закладок **только при отсутствии уже синхронизированного локатора**: валидные значения в `sync` имеют приоритет над локальными для тех же ключей; отсутствующие в `sync` значения берутся из существующего локального хранилища/дефолтов. При первом включении не затирать существующие облачные значения дефолтами нового профиля; документировать поведение при задержанном первом получении удалённых данных, без ложного обещания, что sync уже завершился. Не удалять прежний локальный объект до успешной миграции и подтверждения последующих чтений. **Отдельно учесть переход между Google-аккаунтами:** если установка ранее уже мигрировала настройки либо смена аккаунта известна, отсутствующие облачные ключи **не дополнять автоматически старыми локальными значениями другого аккаунта**. Для такого случая использовать безопасные значения и явное одноразовое подтверждение переноса локальных настроек, если пользователь действительно хочет их загрузить в новый аккаунт; не создавать постоянный переключатель синхронизации. Первую миграцию ранее не мигрировавшего профиля и смену аккаунта различать осторожно, без обещания обнаружить все переходы, когда API не предоставляет достаточных сведений.
7. Сохранить **локальный рабочий слепок настроек** для надёжного старта, работы без сети/Chrome Sync и отказов `storage.sync`. Миграция и двустороннее согласование не должны вызывать циклы записи: изменения из `storage.sync.onChanged`/WXT `.watch` валидируются, применяются к локальному слепку и UI, но не записываются обратно в `sync`, если значение фактически не изменилось. Для Chrome `sync` — источник разделяемых значений при их наличии, для каждого конкретного устройства локальный слепок остаётся резервом; **локальный ID выбранного корня** хранится отдельно, а переносимый локатор — в `storage.sync`. Не ломать `withDataLock`, существующий patch API, preview/flush F05/F06 и переключение поисковика из F04.
8. Применение удалённых настроек из другой вкладки/устройства **без полной перезагрузки страницы и без мигания фонового слоя**. При новых значениях пересчитывать нужные CSS-токены и layout; если пользователь в это время набирает число/email или меняет цвет, сохранять курсор и его незавершённый ввод до завершения локального изменения. Защититься от старых `watch`/async-ответов, двойных событий локальной записи и BroadcastChannel и восстановления уже заменённых значений; реально незатронутые поля не менять.
9. Если запись в `sync` завершилась ошибкой, **локальные настройки, выбранная папка и возможность пользоваться расширением сохраняются**. Показать краткое ненавязчивое предупреждение про ошибку именно синхронизируемого хранилища, не показывая ложное «Синхронизировано», предусмотреть повтор при следующем успешном изменении или явной проверке статуса. Если системная синхронизация выключена, `storage.sync` остаётся работающим локальным хранилищем, это не повод запрещать сохранение. Ошибка или недоступность `storage.sync` в Firefox не должна ломать настройки: в Firefox сохраняется локальный режим; **поддержка синхронизации настроек через Firefox Sync в F07 не обещается**.
10. **Сброс настроек** устанавливает дефолтные значения как для текущего устройства, так и для синхронизируемых ключей, не удаляя реальные закладки и выбранную папку, её локальный ID и синхронизированный локатор. Перед импортом/сбросом завершать или отменять pending writes, чтобы старые отложенные изменения не восстановились поверх новых. Импорт JSON v2 и будущий v3 по прежним правилам может заменить настройки и синхронизировать их; фон и локальные изображения при этом не отправляются в облако. Не удалять всё `storage.sync.clear()` без ограничений: работать только с собственными keys расширения. Сброс визуальных настроек не должен без отдельного выбора пользователя очищать/заменять синхронизированный локатор папки.

### 3. Восстановление выбранной папки между устройствами

11. **Формат локатора:** отдельная версионированная структура в `storage.sync`, например `selectedFolder: { version: 1, anchor: { folderType: "other", syncing: true }, path: ["Speed Dial", "Избранное"] }` (схема — ориентир, окончательные имена полей типизировать). Для стандартной папки `path: []`. `folderType` (`bookmarks-bar` / `other` / `mobile`) определяет системного предка; `syncing` различает аккаунтную и локальную ветви в Chrome 134+, где это свойство доступно. Для нестандартной структуры поддержать только проверяемый полный путь от известного предка. Сегменты — исходные `title`, а не локализованные подписи `FolderChoice.path` с суффиксами `(аккаунт)` или `(локально)`. Не включать в локатор `id`, `parentId`, индексы, URL/содержимое папки, Chrome account ID/email. Валидировать версию, разрешённые типы, допустимую глубину и длину сегментов, размер записи в квоте `sync`; повреждённый локатор игнорировать с понятным уведомлением, не выбирать произвольную папку.
12. **Поиск на другом устройстве:** после получения локатора читать актуальное дерево `browser.bookmarks.getTree()` и сопоставлять **всю цепочку родителей от системного предка** до выбранной папки, тип ветви и признак `syncing` там, где API его предоставляет. Кандидат должен быть папкой, пригодной как источник по правилам F02. Выбирать автоматически **только при единственном доказуемом совпадении**. Несколько одинаково названных папок (включая одноимённых предков), несколько системных `folderType`, несовпадение `syncing`, локальное/аккаунтное дерево и отсутствие идентифицирующих свойств на старых версиях Chrome не должны приводить к угадыванию по первому совпадению. При невозможности безопасно установить единственное соответствие сохранять текущий локальный выбор и предложить ручной выбор.
13. **Приоритет и первая синхронизация:** если валидный локатор уже существует в `sync` и однозначно разрешается, его папка на новом устройстве становится выбранной, а найденный ID сохраняется **только локально**. Если локатор в `sync` отсутствует, а в текущем профиле уже есть пользовательская папка, можно один раз сформировать его из локального выбора; не публиковать автоматический дефолт чистого профиля до завершения первоначального чтения sync и не перезаписывать удалённый выбор «Другими закладками». Если локатор удалённо задан, но пока не найден, оставить рабочий местный корень или безопасный существующий fallback; не заменять облачный локатор этим fallback и не считать ситуацию успешным восстановлением. В Firefox сохраняется действующий локальный выбор.
14. **Ожидание появления папки:** Chrome может доставить данные `storage.sync` **раньше**, чем соответствующую папку Bookmarks Sync. Пока папка отсутствует, хранить синхронизированный локатор как ожидающий, не создавать пустую папку-дубликат и не переключать источник на одноимённую локальную. Повторять разрешение по получению новых sync-данных, реальным изменениям дерева (`bookmarks.onCreated/onMoved/onChanged/onRemoved/onImportEnded`), при новом открытии/активации вкладки, а также после изменения доступного признака `syncing` с защитой от частых повторов; без постоянного polling. Не предполагать, что изменение `syncing` обязательно порождает отдельное событие Bookmarks API. Когда появится единственный корректный кандидат, применить его **только если пользователь не выбрал другую папку вручную после возникновения ожидания**. Подтверждённый ручной выбор имеет приоритет и обновляет локатор в `sync`.
15. **Смена выбора, переименование и ошибки:** при явном выборе другой папки в настройках немедленно применять её существующим механизмом F05, получать новый локатор по актуальному дереву и записывать его в `storage.sync` через ту же упорядоченную очередь/обработку ошибок, что и настройки. Не допускать позднего ответа старого локатора A→B→A, восстанавливающего B. При переименовании или перемещении **самой выбранной папки либо любого из её предков** в Bookmarks API оставлять локальный ID выбранной папки, пересчитывать полный путь после подтверждения изменения и обновлять локатор без циклов; на других устройствах временная несовместимость путей до синхронизации закладок допустима. При удалении/недоступности выбранной папки использовать безопасное поведение F02, **не** перезаписывая удалённый локатор произвольной резервной папкой. Ошибки записи в sync не должны отменять действительный локальный выбор: показать проблему синхронизации и предложить повтор.
16. **Граница гарантий:** если выбранная папка **локальная и не синхронизируется самим Chrome**, сохранять её переносимый путь можно, но нельзя утверждать, что на другом устройстве существует то же содержимое: не переключаться автоматически на одноимённую локальную папку без подтверждения. Объяснить, что для автоматического восстановления нужно сделать папку доступной через синхронизацию закладок браузера, либо вручную выбрать аналог на другом устройстве. `BookmarkTreeNode.syncing` показывает привязку узла к хранилищу аккаунта, но не служит доказательством доставки папки и настроек на другое устройство. Не добавлять скрытую миграцию закладок, автоматическое создание/копирование/перемещение или удаление; без пользовательского действия никаких операций `bookmarks.create/update/move/remove/removeTree`.

### 5. Режим разработчика: постоянный ID расширения и смена Google-аккаунта

23. **Одинаковый ID Chrome-расширения без публикации в Web Store — обязательное условие межустройственной синхронизации.** На двух компьютерах SpeedDial X устанавливается вручную как распакованная Chrome MV3-сборка, возможно из разных каталогов. Убедиться, что ID в `chrome://extensions/` и `chrome.runtime.id` совпадает на обеих установках; без этого данные `storage.sync` относятся к разным расширениям, даже если Google-аккаунт один. Закрепить ID поддерживаемым Chrome способом — **одним неизменным публичным ключом `manifest.key`** в результирующем Chrome-манифесте (с учётом генерации манифеста в WXT). Ключ не должен генерироваться заново при сборке или зависеть от абсолютного пути проекта/выходного каталога. Проверить содержимое сгенерированного манифеста для Chrome и фактический ID **в двух независимых распакованных каталогах**, а не только текст настройки WXT. Использовать именно валидное значение публичного ключа для Chrome, не произвольную строку. Chrome Sync **не обязан автоматически устанавливать распакованное расширение на второй компьютер**: установка на обоих устройствах остаётся ручной. Firefox не должен получать Chrome-специфичный ключ и не должен терять свою сборку. Документация Chrome: `https://developer.chrome.com/docs/extensions/reference/manifest/` (параметр `key`).
24. **Сохранить данные существующей dev-установки.** До фиксации `manifest.key` сравнить текущий ID установленного расширения с ID новой сборки. **Смена ID означает отдельную установку**, прежние `storage.local`, `storage.sync` и IndexedDB/кэш изображений автоматически в неё не переходят; нельзя молча считать это безопасным обновлением. Если сохранение прежнего ID невозможно, **не менять его незаметно**: указать ограничение и безопасный порядок ручного перехода (сначала резервная копия доступным экспортом, затем новая установка, восстановление переносимых данных и ручная проверка). Действующий JSON v2 не переносит favicon/эскизы, поэтому не обещать полного восстановления изображений до F12 и не удалять старую установку ради теста. Сохранять в репозитории при необходимости только **публичный** `manifest.key`, никогда не коммитить приватный `.pem`/ключ подписи или персональные данные; не добавлять OAuth или публикацию в Store.
25. **Безопасное переключение Chrome-аккаунтов A→B, в том числе после перезапуска браузера.** Перед первичным заполнением облачных ключей прочитать их фактическое состояние и убедиться, что старые локальные значения аккаунта A не отправляются автоматически в B. Если у B уже есть синхронизированные параметры, они имеют приоритет, а отсутствующие у B поля не следует восполнять значениями A без осознанного действия пользователя. Если у B данные отсутствуют, а эта установка уже проходила миграцию или принадлежность локальных значений текущему аккаунту сомнительна, **не публиковать их в `sync` молча**: оставить рабочую локальную конфигурацию и дать одноразовый понятный выбор перенести её в аккаунт B либо начать с безопасных значений. При наблюдаемой смене аккаунта в открытой сессии немедленно отменять устаревшие ожидающие облачные записи и заново читать `sync`; при поздних ответах/ошибках не допускать отправки старых значений. Для различения уже завершённой миграции допустима **локальная обезличенная служебная метка**, но email и Google account ID не сохранять ни в `storage.sync`, ни в `storage.local`, ни в JSON, логах или телеметрии. `getProfileUserInfo({accountStatus:'SYNC'})` можно применять для **временного сравнения в памяти**, но он может быть недоступен или не отражать переход, когда Sync выключен. **Не обещать абсолютной изоляции аккаунтов вне гарантий Chrome Sync**: распространение уже находившихся в локальной `storage.sync` данных при смене профиля контролирует сам браузер; в отчёте явно отметить неподтверждённые сценарии реальной доставки между аккаунтами.

### Где работать

`services/settings.ts` (типизированный sync-адаптер/миграция и локальный резерв), при необходимости отдельный небольшой `services/settingsSync.ts`, `composables/useDial.ts` (применение внешних изменений и статус), `services/repository.ts`, `services/bookmarks.ts` (получение локатора выбранной папки, сопоставление дерева, сохранение локального ID), `services/validation.ts`, `types/models.ts`, `components/SyncStatus.vue`, `components/SettingsPanel.vue`, `services/sync.ts`, тесты; `App.vue` и `wxt.config.ts`/`manifest.json` при необходимости для **стабильного ID распакованной Chrome-сборки** (проверять итоговый manifest). Разрешение `storage` уже есть. Не вводить новую авторизацию, аккаунты/OAuth, тяжёлую библиотеку, новый сервер или изменение модели закладок.

| T22 | На B ожидается папка, но пользователь выбрал другую вручную | Ручной выбор побеждает, старый отложенный callback не переключает обратно, новый локатор записан в sync |
| T23 | Источник A — папка только локального дерева, B содержит одноимённую локальную папку | Локатор сохранён, но автоматического ложного сопоставления нет; предложен ручной выбор или включение синхронизации закладок |
| T24 | В sync повреждённый/неизвестной версии локатор, неверная ветвь или длинный путь | Безопасная валидация, никаких ложных переключений/изменений закладок, локальная папка продолжает работать |
| T25 | На A выбранная папка переименована/перемещена/удалена, на B запаздывают события | Для действующей папки локатор корректно обновляется, поздние ответы игнорируются; при удалении не публикуется случайный fallback |
| T26 | На A/B повторные A→B→A, ошибка записи sync, нет выбранной папки на новом профиле | Последний явный выбор остаётся локально, ошибка отражена; нет порчи дерева, неверного выбора или фонового мигания |
| T27 | Tooltip аккаунта: enabled/disabled/unknown/Firefox, hover/focus/click, панель 300 px, до и после F12 | Короткие подсказки соответствуют состоянию; при выключенной синхронизации есть путь к настройкам Chrome и переключатели «Расширения»/«Закладки», при включённой названы настройки/выбранная папка и локальные фон/favicon/эскизы; до F12 нет обещания готового полного переноса, после F12 — экспорт/импорт; текст не обрезается |
| T28 | Две распакованные Chrome MV3-сборки установлены из **разных каталогов**, без публикации в Web Store | У них совпадает реальный `chrome.runtime.id` / ID в `chrome://extensions/`, в обоих итоговых манифестах один валидный публичный `key`; Firefox собирается без Chrome-специфичного ключа |
| T29 | До добавления `manifest.key` уже есть dev-установка с пользовательскими настройками, фоном, favicon и эскизами | Сравнён старый и новый ID; если он меняется, переход **не объявляется бесшовным**, старая установка и её данные не удаляются, ограничения JSON v2 и план резервного копирования указаны |
| T30 | Переключить Google-аккаунт A→B, у B уже есть иные параметры в `storage.sync` | Настройки B имеют приоритет; локальные поля A и их устаревшие pending-записи не отправляются в B автоматически; нет переписывания облачных значений B |
| T31 | Переключить A→B после перезапуска, у B нет облачных настроек; информация об аккаунте отсутствует или недоступна | При уже мигрировавшей установке нет автоматической публикации старого набора A; пользователь может однократно подтвердить перенос или оставить локальные настройки, без хранения Google email/ID |
| T32 | Включить/выключить Chrome Sync, выйти и снова войти, в двух браузерах установлен одинаковый dev-ID | Локальная работа сохраняется, после возвращения Sync не возникает слепой массовой перезаписи; доступность удалённой доставки проверена отдельно; браузер не обязан сам устанавливать распакованное расширение |
| T33 | `manifest.key` и приватные ключи в исходниках, Chrome/Firefox сборках, документации и Git | В репозитории при необходимости только публичный ключ; нет приватного `.pem`, персональных данных или логов с Google account ID; отчёт честно различает проверенный ID и реально доставленные настройки |

**Готово, если:** существующие настройки корректно мигрируют в синхронизируемые ключи Chrome, переносимый выбор папки восстанавливается на другом устройстве при однозначном совпадении синхронизированной папки в Bookmarks API, её ID остаётся локальным; отсутствие/неоднозначность папки не приводит к ошибочному переключению. Изменения настроек применяются на других Chrome-устройствах при действующем Chrome Sync с учётом ограничений браузера, при проблемах продолжается локальная работа; **блок синхронизации показывает только аккаунт и единый статус профиля, а дополнительные сведения — в tooltip, не обещая неподтверждённую облачную доставку или пока недоступный полный импорт изображений**. **Для распакованных dev-сборок дополнительно подтверждён одинаковый Chrome extension ID; переход со старого ID не выдаётся за безопасное обновление без миграции, а смена Google-аккаунта не запускает слепую публикацию старых локальных настроек.** **Один коммит:** `feat: sync settings across Chrome devices`. **Остановись после F07: F09 не начинай.**

## F08 · P1 · Единые окна добавления и редактирования закладки

### Цель и границы

Привести `components/BookmarkDialog.vue` к **простому, гармоничному и одинаково понятному интерфейсу создания и изменения настоящей закладки Chrome/Firefox**. Это самостоятельный UI/UX-этап **после синхронизации F07 и до улучшения панели категорий F09**. Сохранить единую форму/компонент для двух режимов, уже работающие сценарии URL, названия, редактирования, смены папки через Bookmarks API и управляемой пользователем генерации эскиза (при добавлении включена по умолчанию). Использовать токены оформления F06 (радиус, прозрачность, blur, акцент, стеклянные поверхности), без нового фреймворка форм или тяжёлого редизайна остальных модальных окон. Не создавать новые типы закладок и не дублировать их URL/названия в локальном хранилище: настоящие закладки остаются в Bookmarks API; для защиты пользовательских названий допустим лишь небольшой локальный служебный признак происхождения автозаголовка.

### Интерфейс

1. **Одно компактное модальное окно с двумя режимами:** заголовок `Добавить закладку` / `Изменить закладку`; одни и те же поля в одном порядке: **Адрес сайта**, **Название**, **Категория**. Отличаются лишь значения и основное действие `Добавить` / `Сохранить`. В текущем коде URL/название представлены в основном placeholder-ами, а категория доступна только при редактировании — исправить. Сохранить нормальные текстовые подписи над полями даже при заполнении (не заменять подписи одним placeholder). Никаких отдельных вкладок внутри окна, многоступенчатого мастера, огромной карточки-превью или дополнительных экранов без необходимости.
2. **Размер и композиция:** адаптивная ширина ориентировочно **400–440 px** на широком экране (нынешние 300 px слишком узки для URL); на мобильных viewport — ширина экрана с безопасными полями, без горизонтального скролла. Аккуратная вертикальная ритмика, равные отступы, одинаковая высота текстовых полей и select, видимые hover/focus/disabled/error; внизу **только одна основная кнопка** `Добавить` / `Сохранить`; отдельную кнопку `Отмена` не добавлять. Крестик закрытия в заголовке оставляем; клик по фону вне окна и Escape также закрывают форму без сохранения. Основное действие не должно превращаться в несколько конкурирующих полноширинных кнопок. Учитывать тему F11, когда она будет реализована; на этапе F08 не внедрять темы преждевременно.
3. **URL** — обязательный, с автофокусом при создании, предсказуемой вставкой и редактированием длинных адресов без выхода за границы окна. При отправке использовать действующую `normalizeUrl` и исключение опасных схем (никаких `javascript:`/`data:`). Невалидный или пустой адрес подсвечивается у поля и получает короткое, доступное сообщение; не закрывать окно и не терять набранные значения. Не выполнять автоматическую загрузку внешней страницы ради определения названия/эскиза при простом вводе адреса.
4. **Название** — необязательное. При добавлении, если пользователь оставил поле пустым и включён «Создать эскиз сайта», после успешного захвата подставить **достоверное название страницы** из существующего `requestThumbnail()`/`CaptureResponse.title` (`browser.tabs`), а не hostname. До успешного получения названия безопасно создать закладку с временным доменным названием: при ошибке захвата или неподходящем заголовке сохраняется домен, без дубликата закладки. Если пользователь ввёл название, **никогда не заменять его заголовком страницы**, независимо от состояния checkbox; если захват выключен, пустое поле означает прежний fallback по hostname. Не выполнять сетевой запрос или открытие сайта только при вводе URL: название извлекать лишь в рамках явно запускаемого захвата. При редактировании показывать текущее название, допускать произвольный пользовательский текст; явная очистка поля означает новый автоматический fallback-домен и помечается как автоматически созданное имя для возможного последующего обновления эскиза. Если при смене URL ранее подтверждённый маркер `auto-domain` относился к старому адресу и пользователь не редактировал название, сначала заменить временное доменное имя на домен **нового** URL и привязать маркер к нему; после успешного захвата допускается замена на название новой страницы. Если старое имя было введено пользователем или его происхождение неизвестно, не менять его автоматически. Если меняются только имя/категория, URL и локальные изображения не должны теряться без причины; сохранять нормальный фокус и постоянные подписи.
5. **Категория доступна и при добавлении, и при редактировании.** Предлагать действительную выбранную исходную папку F02 и её непосредственные доступные категории из Bookmarks API; для нового элемента по умолчанию выбирать **текущую активную категорию**, а если она недоступна — корень. В режиме редактирования показывать **реальную текущую родительскую папку закладки** и позволять переносить её выбором другого пункта, с прежними правилами валидации. Использовать реальные ID только для операций, видимые подписи — из текущих данных; в F09 подпись корня станет названием исходной папки с иконкой `folder-open`, не закреплять в форме текст `Главная`. Не показывать глубокие, управляемые и чужие папки, не переносить плитку при одном открытии списка. При создании передавать выбранную папку непосредственно в сохранение (`repository.add` или эквивалент с валидацией принадлежности), а не создавать закладку в одном месте с последующим скрытым перемещением. Не добавлять в эту форму функцию создания новой категории — управление категориями остаётся F09.
6. **Создание эскиза** — checkbox `Создать эскиз сайта` доступен только при добавлении и **включён по умолчанию**, но пользователь может снять отметку; краткое пояснение: `Сайт временно откроется для снимка и определения названия, если оно не указано`. Состояние по умолчанию при каждом новом открытии формы — включено, без дополнительного глобального параметра. Не выполнять захват до нажатия `Добавить` и не отправлять изображение в `storage.sync`. При редактировании checkbox не нужен: **если нормализованный URL изменился после сохранения, автоматически обновлять эскиз и favicon** через существующий механизм временной вкладки; если URL не изменился, не запускать захват. Дополнительный переключатель для смены URL не вводить. Ручное обновление изображения из контекстного меню остаётся доступным. Если закладка успешно сохранена, но захват не состоялся, **закладка остаётся с пользовательским названием или доменом**, ошибка показывается отдельно, без автоматической повторной попытки, нового открытия диалога и дубликатов. Сохранить существующий путь `requestThumbnail`/`updateImages`, не реализовывать новую систему скриншотов.
7. **Единая иерархия действий:** крестик, клик по фону вне модального окна и Escape закрывают форму без записи черновика; отдельной кнопки `Отмена` нет. Открытие формы и её закрытие без сохранения не меняют данные; `Добавить` / `Сохранить` — только после валидации, одна операция на нажатие (защита от двойного submit). Enter из текстовых полей выполняет нативную отправку формы, а не перехватывает глобальные горячие клавиши; если открыто меню выбора категории, работают стандартные клавиши select. Во время сохранения предотвратить повторное нажатие и случайное закрытие; показывать компактное `Сохранение…`, без выдуманного прогресса. По завершении окно закрывается, список обновляется, фокус возвращается к вызвавшему контролу или ближайшему доступному элементу. Углублённая клавиатурная навигация по всей странице запланирована отдельно в F10, но базовая доступность модального окна обязательна уже здесь.
8. **Ошибки у конкретных полей и общая ошибка API:** ошибочный URL — под URL; исчезнувшая/недоступная категория — у select; конфликт внешней модификации, отказ Bookmarks API или отсутствие прав — общее заметное сообщение внутри окна, с сохранением заполненных полей и возможностью повторить. Сообщения `role=alert`/`aria-describedby`, focus-visible и корректная фокусировка; не показывать технический стек ошибок пользователю. При внешнем удалении/перемещении закладки ничего не создавать взамен автоматически. При выборе категории проверять принадлежность/доступность перед записью, не полагаться только на устаревший список.
9. **Визуальная согласованность:** входящие формы наследуют токены F06, типографику и элементы управления настроек, не добавляют отдельные неунифицированные цвета, резко отличающиеся тени и опасные полупрозрачные инпуты. Не перекрашивать эскизы, favicon и существующие текстовые плитки. Не превращать простую модалку в панель настроек, не добавлять декоративные картинки/анимации. Общие правки `ModalDialog.vue` делать без регрессии окон F11 и остальных модалок; сохранить `aria`-имена, Escape, блокировку при busy и восстановление фокуса. Сохранять пользовательские параметры оформления и корректное поведение при `prefers-reduced-motion`.
10. **Границы работы:** одна законченная функция в одном осмысленном коммите; не начинать F09 (DnD/категории), F10 (полная клавиатурная навигация) и другие этапы. Существующие `BookmarkDialog.vue`, `ModalDialog.vue`, `App.vue`, `services/repository.ts`, `services/thumbnails.ts`, `services/bookmarkAssets.ts`/`services/database.ts`, модели и тесты дорабатывать только по необходимости. Не менять CRUD других папок/их структуру, не инициировать массовую фоновую загрузку эскизов и не добавлять новые permissions.
11. **Обновление названия при ручном обновлении эскиза:** существующая команда обновления эскиза из контекстного меню может одновременно заменить автоматически подставленный **домен** на полученное достоверное название сайта. Только если известно, что имя было назначено расширением автоматически и с тех пор пользователь не устанавливал собственное имя. Если пользователь сам ввёл название (в том числе строку, совпадающую с доменом), сохранить его дословно. При автоматическом захвате из-за смены URL применять ту же защиту названия: менять только достоверно автоматически подставленный домен, а пользовательское название оставлять без изменений. Изменение одной категории, загрузка favicon, открытие закладки и фоновое обновление данных не должны самопроизвольно изменять название. После успешного получения названия сохранить его через штатный Bookmarks API, соблюдая защиту от потери данных и внешних изменений.
12. **Надёжное различение автозаголовка и пользовательского имени:** **не определять происхождение по одному сравнению `title === hostname`** — пользователь вправе вручную написать домен. При создании с пустым именем сохранять минимальный локальный маркер `auto-domain` для конкретной закладки (с привязкой к ID и URL); при явном вводе/изменении имени удалять или переключать этот маркер в состояние, запрещающее автопереименование. После успешной подстановки названия сайта снять признак ожидающего доменного fallback: повторное обновление эскиза не переименовывает уже нормальную закладку. Перед записью повторно прочитать актуальные ID, URL и название закладки через Bookmarks API; при внешнем/ручном переименовании, смене URL, удалении или параллельной операции **пропустить автопереименование**, не откатывать чужую правку и не привязывать заголовок одного URL к другому. Локальный маркер не является копией закладки, не содержит названия/URL-истины и **не попадает в `storage.sync`**. Для старых закладок без надёжного маркера происхождение **неизвестно**: по одному совпадению с доменом не перезаписывать название автоматически. При сбросе/удалении корректно очищать маркеры, а в будущей F12 предусмотреть их привязку к новым ID при импорте JSON v3. Заголовок страницы считать пригодным только после очистки пробелов, проверки длины/валидности и исключения пустого или неинформативного значения; ошибки получения заголовка не мешают сохранению изображения.

13. **Автоматический захват при смене URL:** при сохранении редактируемой закладки сначала валидировать и записать новый нормализованный адрес через Bookmarks API, затем без дополнительной галочки вызвать существующий `requestThumbnail()` для **нового адреса**, временно открыть и закрыть вкладку, обновить favicon и локальный эскиз. При неизменном нормализованном URL — даже если меняются название или категория — захват не запускать. Изображения и результат от старого URL не показывать как новые; учитывать привязку к URL в локальном кэше. Если новый сайт не загрузился, изменился во время захвата или снимок завершился ошибкой, **новый URL и сохранённое название не откатывать**, вывести короткое сообщение о неудачном эскизе и показать актуальный favicon либо Opera-style текстовую плитку. Не создавать дублей закладок, не делать скрытых повторных попыток, не добавлять прогресс-бар/отдельную кнопку, не менять существующий цикл временной вкладки. Перед применением запоздавшего снимка/заголовка повторно сверять существование закладки, её ID, URL, название и локальный признак `auto-domain`; не перезаписывать ручную или внешнюю правку. Автоматически менять название только по правилам пп. 4, 11–12.

## F09 · P1 · Управление плитками и категориями

**Статус: реализована · 20.10.2026.** Постоянная корневая вкладка с фактическим названием и иконкой папки, единый прокручиваемый ряд категорий, модальное создание/переименование и безопасная сортировка через Bookmarks API. Проверки и ограничения описаны в `docs/verification.md`; сценарий `test:categories`. F10 не начиналась.

### Цель и границы

Объединить прежние задачи улучшения Drag-and-Drop плиток и UX категорий в **одну завершённую пользовательскую функцию**. Пользователь должен ясно видеть, где находится плитка, какая категория выбрана, как создать новую и куда попадёт элемент после перетаскивания. Реальное дерево `browser.bookmarks` остаётся единственным источником данных и порядка. **Не переписывай уже работающие механизмы:** в текущем коде есть `CategoryDialog.vue`, модальное создание/переименование, кнопка `+`, контекстное меню категорий и базовый DnD. Перед изменениями проверь их на рабочей копии и исправь лишь расхождения с требованиями.

**Границы:** F09 отвечает за поведение категорий и перестановку элементов **мышью/указателем**, включая базовые нативные действия Tab/Enter и доступные названия контролов. **Углублённая клавиатурная навигация, обработка фокуса во всём приложении и keyboard-only альтернатива DnD — отдельная F10.** Не вводи в F09 произвольные глобальные сочетания клавиш и новый фреймворк перетаскивания.

### Панель категорий и управление ими

1. **Первая вкладка — виртуальная корневая категория с настоящим названием выбранной в настройках папки-источника**, а не с фиксированной подписью «Главная». Она отображается всегда в режиме категорий при действительном источнике, даже если папка пуста и реальных категорий нет. Например, при выборе «Другие закладки» первый таб называется «Другие закладки», при выборе «Speed Dial» — «Speed Dial». Для подписи используй то же отображаемое название папки, что в выборе папок настроек F02 (`FolderChoice.title`, включая локализованные названия системных папок), **не полный путь и не локальный ID**. Это тот же выбранный корень Bookmarks API, представляющий его непосредственные закладки, **не новая дочерняя папка**. **Перед названием первой вкладки всегда показывай небольшую иконку открытой папки (`folder-open`)**: она обозначает выбранную папку-источник и визуально отличает её от обычных категорий. Иконка остаётся при активном и неактивном состоянии вкладки, не имеет отдельного действия, использует цвет текста и не дублируется в обычных категориях. Название остаётся главным читаемым элементом; иконку сделай компактной (ориентир 14–16 px), декоративной для скринридера (`aria-hidden`), а доступное имя вкладки — полное имя папки без слова «Главная». Не используй иконку домика, чтобы не создавать впечатление отдельной домашней страницы. Виртуальная вкладка всегда первая, не переименовывается, не удаляется и не перетаскивается; переименовать саму исходную папку можно только предусмотренными средствами браузера, без нового действия в панели категорий. Если источник недоступен, сохраняй существующее сообщение и переход в настройки, не показывай устаревшее название и не создавай фиктивных папок.
2. **Создание категории — через пункт «Новая категория» контекстного меню панели или страницы.** Кнопки `+` в ряду нет. Ввод названия открывается в общей модалке с кнопкой «Создать», Enter сохраняет, Escape отменяет. При пустом имени сохранение отключено; ошибка API остаётся внутри окна. После успеха новая категория выбрана.
3. Категории — только **непосредственные дочерние папки выбранного корня**. Более глубокие папки не отображать как отдельные категории, не перемещать и не трогать автоматически. **Фиксированное специальное имя «Главная» больше не нужно:** дочерняя реальная папка с названием «Главная» отображается обычным образом, если название корня другое. Если дочерняя папка совпадает **по отображаемому названию с выбранным корнем** (например, корень «Работа» и дочерняя «Работа»), отличай реальную категорию подписью `Работа (папка)` **только в UI**. Корневая вкладка должна сохранять точное имя выбранной папки, реальные названия в Bookmarks API не менять. Операции отличай по ID/признаку `virtual`, а не по тексту названия.
4. Панель располагается между мультипоиском и плитками. Корень и реальные категории составляют единый горизонтально прокручиваемый ряд; поиск остаётся справа. При нехватке места прокручивается весь ряд. На 360/1280/1920px нет переполнения страницы и наложений.
5. Переименование реальной категории открывает ту же модалку с текущим названием и кнопками «Сохранить»/«Отмена». Enter сохраняет непустое имя, Escape отменяет; blur не сохраняет. Общие ModalDialog/PanelHeader и токены оформления обеспечивают единый фон, радиус, прозрачность, акцент, размытие и переходы 250 мс.
6. Перед удалением реальной категории оставь явное подтверждение: `removeTree` удаляет **всех потомков, в том числе невидимые глубокие папки**, с возможной синхронизацией. Отмена не вызывает API мутаций. Защити от удаления выбранного корня F02/его виртуальной вкладки с названием папки; это удаление **одной конкретной реальной категории**, а не массовая очистка выбранной папки (последняя удалена в F02).
7. Выбор категории меняет отображаемые плитки, но не перемещает их. Удаление/перемещение выбранной категории извне возвращает пользователя в **виртуальную вкладку корня**, даже если она пуста. Переключение выбранной папки в F02, её автоматическое восстановление через F07 и **переименование выбранной папки извне в менеджере закладок** должны обновлять подпись первой вкладки без перезагрузки страницы и изменения пользовательских данных. Подпись выводится из актуального дерева Bookmarks API, не хранится второй копией в настройках/`storage.sync`, не зависит от старого текста «Главная».
8. При открытом локальном поиске F03 сохраняй нынешнее поведение скрытия категорий с резервированием высоты и без скачков layout; после закрытия восстанавливай выбранную категорию и положение списка. **В результатах локального поиска** для непосредственных закладок корня показывай актуальное название выбранной папки вместо исторической подписи «Главная», не меняя сам алгоритм поиска. Длинное имя корня в первой вкладке ограничивай по доступной ширине с `…`, сохраняя **полный текст в `title`/доступном имени и в подсказке**, без переносов и вытеснения поиска или реальных вкладок на экранах от 360px. **Иконка папки при усечении текста остаётся видимой**; не создавай дополнительную кнопку или отдельный тултип для неё. Не встраивай поиск в F09 заново. Оформление из F06 (радиус, прозрачность, размытие) обязательно применяется к табам/полям/меню.

### Перестановка плиток и категорий

9. Перетаскивание плиток изменяет порядок **только среди непосредственных закладок текущей отображаемой категории** (включая виртуальную вкладку выбранного корня); настоящие индексы сохраняются через `repository.reorder()` / `browser.bookmarks.move`. Не создавай дублирующее хранилище порядка и не двигай скрытые глубокие папки. При смешанных прямых ссылках и дочерних папках сохраняй их целостность.
10. Показывай различимые состояния **перетаскиваемой плитки, допустимой цели и позиции вставки**. После drop результат должен совпасть с фактическим порядком в Bookmarks API. Не допускай двойной операции `drop`/`dragend`, неожиданных reorder при drop на самого себя или вне допустимой области; обычный клик по ссылке не должен срабатывать после drag.

## F10 · P2 · Клавиатурная навигация и доступность

### Цель и границы

Обеспечить последовательное **управление всей новой вкладкой без мыши**, используя уже существующие компоненты и итоговую панель категорий из F09. Не смешивать эту работу с дополнительным редизайном категорий или новой логикой drag-and-drop: F09 — интерфейс и мышь, **F10 — фокус, клавиатура, семантика и доступная альтернатива перестановке**. Сохраняй стандартное поведение браузера и инпутов.

### Требования

1. **Tab/Shift+Tab** последовательно обходят строку мультипоиска F04, доступные категории, контекстное меню создания, локальный поиск F03, плитки, настройки и другие видимые действия. Невидимые элементы, закрытые меню и скрытая панель категорий во время локального поиска не попадают в tab order. Не отменяй браузерные сочетания (`Ctrl+L`, `Ctrl+T`, `Ctrl+W` и т.п.).
2. Для каждого интерактивного элемента нужен **видимый `:focus-visible`** с достаточным контрастом на любом фоне и при настройках F06 (прозрачность 0–50%, blur вкл./выкл., разные скругления). В коде `App.vue` уже встречается глобальное подавление outline — убрать или точечно компенсировать, не ломая существующий hover.
3. **Навигация стрелками по плиткам** в текущей сетке: Left/Right — предыдущая/следующая плитка строки; Up/Down — визуально соответствующая плитка соседнего ряда с учётом фактически рассчитанного числа столбцов, при коротком последнем ряде переход к последней доступной. Home/End — начало/конец текущего ряда. На краях фокус остаётся на валидной плитке. Алгоритм документируй и покрывай тестами на 2/6/12 столбцов, изменение ширины и динамическую выдачу.
4. Не меняй порядок данных при навигации. **Enter по плитке открывает её URL**, по категории выбирает категорию, по пункту «Новая категория» открывает модалку; Space на кнопках действует нативно. Перемещение фокуса стрелками не открывает ссылки. Ссылки сохраняют обычные браузерные контекстные операции.
5. В категории обеспечь клавиатурный доступ к выбору таба, созданию, модальному изменению названия и открытию контекстного меню (Shift+F11 / Menu). Виртуальная вкладка выбранной папки не имеет действий rename/delete независимо от текста её названия. При горизонтальной прокрутке выбранный фокусируемый таб должен оставаться видимым; не перехватывай стрелки, когда фокус находится внутри поля модалки.
6. **Доступная альтернатива DnD:** перестановку плиток и реальных категорий, доступную мышью в F09, сделай возможной без мыши (например, через компактные контекстные действия `Переместить влево/вправо` или иной простой способ). Используй те же безопасные операции repository и не создавай второй порядок; недоступные направления отключай. Для плиток не добавляй перемещение *между категориями* через drag-логику — текущий select в `BookmarkDialog` остаётся достаточным способом переноса.
7. **Контекстные меню:** открытие правой кнопкой не должно быть единственным способом; поддерживай Shift+F11/контекстную клавишу, фокус на первом/выбранном пункте, Up/Down по пунктам, Enter/Space для действия, Escape для закрытия и возврат фокуса на исходную плитку/категорию. Фокус не должен оставаться в удалённом DOM.
8. **Диалоговые окна и панель настроек:** при открытии фокус переводится на осмысленный элемент; в настоящем модальном окне Tab/Shift+Tab остаётся в пределах окна; Escape закрывает только актуальный верхний слой без сохранения черновика и возвращает фокус на элемент-вызвавший диалог. Панель настроек может быть немодальной только при корректном управлении доступностью/фокусом и исключении взаимодействия со скрытой основной страницей; выбери единый проверяемый подход.
9. **Поиски не конфликтуют:** мультипоиск F04 сохраняет ArrowUp/Down для провайдерских подсказок, Enter для выбора/отправки, Escape для закрытия подсказок; локальный поиск F03 сохраняет `/` только вне input/textarea/select/contenteditable/модальных окон. Глобальные стрелки не должны срабатывать во время набора текста, при IME composition или работе с select.
10. **Динамические обновления:** удаление активной закладки/категории, изменение порядка, переключение источника F02, появление/исчезновение результатов поиска или внешний апдейт Bookmarks API не оставляют фокус на body или скрытом элементе; выбирай ближайший живой элемент или логичный контейнер. Не выполняй непрошенные API-записи ради восстановления фокуса.
11. У интерактивных компонентов корректные accessible names/labels, `aria-expanded`, `aria-controls`, `aria-selected` и роли только по подходящему паттерну (navigation buttons vs tabs vs menu vs listbox). Не навешивай одновременно конфликтующие `role` и `aria-pressed`. Сообщения об ошибках/недоступности доступны screen reader без бесконечных `aria-live` объявлений.
12. Проверь Chrome и Firefox, клавиатурный сценарий **от открытия новой вкладки до добавления, поиска, редактирования, сортировки и удаления тестовой плитки**, экраны 360/1280/1920 и `prefers-reduced-motion`. Никаких зависимостей ради нескольких обработчиков, если хватает существующего Vue-кода.

### Где работать

`App.vue`, `components/BookmarkGrid.vue`, `components/ContextMenu.vue`, `components/BookmarkDialog.vue`, `components/CategoryDialog.vue`, `components/BookmarkSearch.vue`, `components/SearchBar.vue`, `components/SettingsPanel.vue`, диалоги и при необходимости небольшой `utils/keyboard.ts`/composable. Архитектуру F09 и работу Bookmarks API не менять без необходимости. Разрешено добавить **только минимально нужные UI-действия** для клавиатурной сортировки.

## F11 · P3 · Светлая, тёмная и системная темы

### Цель

Добавить выбор темы **`Системная` / `Светлая` / `Тёмная`**, сохраняя общий характер SpeedDial X (сетка, настраиваемый акцент F06, собственный фон). Тёмная тема — не полная смена дизайна и не набор пресетов.

### Требования

1. Выбор темы — один select/segmented control в настройках. По умолчанию — **`Системная` для новых пользователей**, но при миграции существующих настроек без поля темы обеспечь разумный нейтральный результат; если это визуально ломает привычный вид у существующего пользователя, используй совместимый первоначальный fallback. Решение зафиксируй тестом и README.
2. `Системная` следует текущей светлой/тёмной теме Windows (и другой поддерживаемой ОС) через `prefers-color-scheme`: при переключении системной темы уже открытая вкладка меняет оформление автоматически, без перезагрузки, дополнительного действия пользователя и заметного мигания. Отслеживай изменение системного предпочтения, например через событие `change` у `matchMedia`, а не только при первом открытии страницы. `Светлая` и `Тёмная` игнорируют изменение системного режима.
3. Вынеси цвета текста/панелей/кнопок/диалогов/подсказок/полей в ограниченный набор CSS-переменных или Tailwind design tokens. Не дублируй множество несогласованных `dark:` классов, которые трудно поддерживать.
4. Текстовые плитки F01 сохраняют детерминированные цвета и WCAG-контраст в обеих темах; изображения и favicon не перекрашивать. Состояния hover/focus, ошибки, выбранный акцент F06 и его оттенок наведения, нижняя подпись скриншотов и фон должны оставаться читаемыми.
5. Пользовательское фоновое изображение имеет приоритет над тематическим базовым цветом фона, без потери изображения и без насильственного затемнения, делающего фон непохожим на выбранный. Текст и UI должны оставаться видимы на фоне.
6. Настройка сохраняется через действующий механизм WXT Storage и Chrome Sync после F07. Добавь новое поле в `Settings` и валидацию, сохрани совместимость с текущим импортом/экспортом JSON v2; не внедряй формат JSON v3 раньше F12. В F12 тема будет включена в полный перенос пользовательских настроек.
7. Не добавляй автоматические расписания, анимированные темы, редактор цветов, пресеты, удалённые подборки обоев.

**Файлы:** `App.vue`, `components/SettingsPanel.vue`, `assets/` CSS, `types/models.ts`, `services/validation.ts`, `services/settings.ts`; затронутые UI-компоненты поднимают токены из общей темы.

## F12 · P2 · Управление данными: полный импорт и экспорт JSON v3 с изображениями

### Цель

Текущий JSON v2 переносит папки, URL, названия, порядок, настройки и фон, но **не** переносит screenshots/favicon. В дополнение к единому переносимому JSON **версии 3** со всеми пользовательскими данными (включая локальные изображения в Base64) **полностью упростить интерфейс управления данными**. Вместо трёх кнопок в настройках, двух отдельных окон импорта/экспорта и большого текстового поля предоставить **одну кнопку «Управление данными» и одно компактное модальное окно** с тремя действиями: экспорт, импорт и сброс настроек и кэша. Без собственного облачного сервиса.

### Интерфейс управления данными — обязательный UX

1. В `SettingsPanel.vue`, в секции «Данные», оставить **одну кнопку «Управление данными»**. Убрать отдельные кнопки `Импорт`, `Экспорт` и `Сбросить настройки и кэш` из панели; не дублировать те же действия в других местах. При открытии окна корректно завершать незавершённое автосохранение настроек F05, не терять пользовательский ввод и не создавать гонок.
2. По нажатию открывается **одно модальное окно «Управление данными»** в оформлении F06/F11. На его стартовом экране — три ясно различимые действия с небольшими тематическими иконками, краткими пояснениями и понятной интерактивной областью/кнопкой для каждого: **«Экспорт»**, **«Импорт»**, **«Сбросить настройки и кэш»**. Экспорт и импорт визуально нейтральны, сброс отделён и обозначен как потенциально опасный. Избегать длинного текста, большого пустого пространства, лишних настроек, дублирующих кнопок и дополнительных диалогов. В тесном окне (включая 320–360 px) строки не переполняются.
3. **Экспорт:** нажатие «Экспорт» сразу запускает создание JSON v3 и скачивание файла `.json`, например `speed-dial-backup-YYYY-MM-DD.json`; **без второго модального окна, предпросмотра JSON, textarea, ручного копирования или отдельной кнопки «Сохранить в файл»**. Не утверждать, что файл уже сохранён, пока известно только о запуске загрузки; системный диалог «Сохранить как» зависит от настроек браузера. При ошибке создания, превышении лимита или запуске скачивания — понятная ошибка в этом же окне. На время формирования файла есть краткий статус и блокировка повторного запуска; не закрывать окно автоматически при неудаче.
4. **Импорт:** нажатие «Импорт» открывает системный выбор `.json` (скрытый `input[type=file]` допустим); никаких текстовых полей, вставки JSON вручную и отдельного окна импорта. После выбора файла в **том же модальном окне** появляется небольшой этап просмотра результата полной валидации: имя файла, сколько будет добавлено закладок и категорий, **конкретная папка назначения** (селект доступных папок, по умолчанию текущая выбранная), какие настройки/изображения импортируются, предупреждение о возможных дублях и Chrome Bookmarks Sync. Кнопки «Импортировать» и «Отмена/Назад» — только на этом этапе. Название и путь папки должны быть однозначны даже при совпадающих именах. Не создавать и не перемещать реальные закладки до отдельного подтверждения; при ошибке чтения/валидации показать сообщение без побочных эффектов, разрешить выбрать другой файл. Если доступной папки нет, импорт недоступен с понятным объяснением; экспорт и сброс не должны блокироваться из-за этого.
5. **Сброс:** нажатие «Сбросить настройки и кэш» раскрывает **подтверждение внутри того же окна**, без второго модального окна и без `window.confirm()`. Ясно указать последствия: параметры возвращаются к значениям по умолчанию, фон, локальные favicon/эскизы удаляются **только на этом устройстве**, а настоящие закладки, категории и выбранная папка остаются. Уточнить, что после F07 сброс синхронизируемых параметров может примениться и на других устройствах с тем же Chrome Sync. Подтверждение — отдельная явно обозначенная опасная кнопка, рядом «Отмена/Назад». Закрытие окна, Escape и отмена не должны запускать сброс. Не возвращать массовую очистку дерева закладок, удалённую в F02.
6. **Одно окно — несколько состояний, не несколько окон:** стартовый список действий, проверка/подтверждение импорта, подтверждение сброса и результаты/ошибки отображаются **в пределах одного модального компонента**. Не открывать вложенные диалоги и браузерные `alert`/`confirm`. После завершения импорта показать краткий итог, включая частичный успех при ошибке. После сброса — достоверное подтверждение фактически выполненного действия. После экспорта можно остаться на стартовом экране со статусом запуска скачивания.
7. При чтении файла, сборке экспорта, импорте и сбросе блокировать конфликтующие действия и повторные запуски; корректно обрабатывать закрытие, отмену, повторный выбор того же файла и сбои. Для необратимых операций не отменять текущую запись «в воздухе» простым закрытием окна. Разумное управление фокусом: при открытии он внутри окна, после закрытия возвращается на кнопку «Управление данными»; `Tab`, `Enter`, `Escape` и сообщения об ошибках доступны с клавиатуры и скринридеру. Не ломать F10, общую визуальную систему и режимы темы.
8. Сброс и импорт должны учитывать F07: **не очищать весь `chrome.storage.sync` целиком**, не удалять переносимый локатор выбранной папки при сбросе, не смешивать локальный кэш и синхронизируемые настройки, не допускать неожиданных перезаписей при одновременном редактировании. Импортируемые настройки применяются только в рамках подтверждённой операции и по действующим правилам сохранения; влияние на другие устройства объяснять там, где это существенно.

### Требования к формату и надёжности

1. Добавить явный `version: 3`, упорядоченный список записей категорий/закладок и полный набор пользовательских настроек. `background` хранить как валидированное изображение Base64/data URL; favicon и thumbnail — в том же JSON (при наличии). Категории — только первый отображаемый уровень.
2. Идентификаторы `browser.bookmarks` **не переносим между профилями**. Выбранная папка F07 определяется на другом устройстве переносимым локатором через Chrome Sync; при импорте пользователь **явно подтверждает папку назначения**, выбранную в интерфейсе управления данными. Нельзя переносить сырой `rootFolderId`, автоматически подменять назначение по старому локатору или создавать системные папки. В JSON каждому элементу можно назначить **внутренний export-entry key**, используемый только для связывания изображений с соответствующей записью; нельзя принимать профильный bookmark ID за переносимый идентификатор.
3. Сохраняй порядок элементов (в корневой вкладке выбранной папки и отдельных категориях) и порядок категорий. Дубликаты `url` или `title` допустимы: изображения должны быть привязаны **к конкретной записи**, а не только к URL. Смена ID после импорта не должна перепутать кэш. Служебный признак `auto-domain` из F08 (если он достоверен) переносить в JSON v3 вместе с конкретной записью и восстанавливать для нового bookmark ID; не экспортировать сырые локальные ID и не выводить признак из совпадения имени с доменом.
4. При экспорте извлекать только локальные Blob `[bookmarkId+url]` из Dexie и фон. Отсутствующий/битый thumbnail или favicon **не** делает экспорт невозможным: предупреждение/пропуск конкретного ресурса вместо потери закладок; не выполняй сетевых запросов или автоматического захвата в ходе экспорта.
5. Бинарные данные конвертировать в Base64 асинхронно, без пропуска MIME типа; импорт проверяет **разрешённые растровые MIME, размер, корректный base64** и ограничения до записи. Ни SVG, ни HTML, ни исполняемые payload принимать нельзя.
6. Во избежание неограниченной нагрузки установи разумные документированные лимиты на файл, число записей и изображения; существующие ограничения JSON v2 и отдельных Blob учти. Не пытайся проглотить много гигабайт памяти. При слишком большом экспорте покажи понятное сообщение (можно предложить экспорт без изображений отдельной опцией **только внутри этой функции**, если большой JSON не помещается; не усложнять обычный интерфейс по умолчанию).
7. **Импорт v3:** сначала полностью прочесть, разобрать, проверить все элементы, URL, один уровень категорий, изображения, размеры и поля настроек. Затем показать встроенный этап проверки/подтверждения из раздела UI: операция **добавит** реальные закладки и папки в выбранный корень, возможны дубликаты, браузер может синхронизировать новые закладки.
8. После подтверждения через Bookmarks API последовательно создать новые записи с новыми ID и восстановить связанный кэш Blob именно по возвращённым ID/URL. Настройки/фон применить согласно текущему поведению. Обработать частичный успех: Bookmarks API не транзакционный, поэтому **сообщить, сколько реально создано** и что при повторе возникнут дубликаты; не утверждать ложный rollback. При ошибке сохранения картинки созданная закладка остаётся.
9. Не заменять и не чистить настоящие существующие закладки молча. Сохрани ограничения корневой папки и безопасность URL. Не включай аккаунты, email-токены, cookies, sync/account IDs, глубокие папки вне отображаемой модели.
10. Историческая миграция Web SQL или импорт других Speed Dial **вне задачи**. Существующий импорт v2 можно сохранить как минимальную совместимость, если это не мешает v3, но не разрабатывай отдельную систему устаревших форматов; **не ломай v2 молча**, если поддержку оставляешь. В README явно перечисли поддерживаемые версии.
11. Экспортируемые настройки обязательно включают уже существующие поля (`F04`, `F05`, `F06`, а также тему `F11`) и прочие реально реализованные пользовательские настройки; параметры F13/F14 включать, только если эти функции уже внедрены. Не добавляй будущие функции «попутно». Не включай вычисляемые цвета текстовых плиток F01.

**Файлы:** `components/SettingsPanel.vue` (одна кнопка «Управление данными»), `components/ImportExportDialog.vue` (заменить/переименовать в единое окно управления данными без textarea; убрать старые режимы отдельных окон), `components/ModalDialog.vue` при необходимости, `App.vue` (единый поток импорта/экспорта/сброса без `window.confirm()`), `services/importExport.ts`, `services/repository.ts`, `services/bookmarkAssets.ts`, `services/database.ts`, `services/images.ts`, `types/models.ts`, тесты. Используй текущую модель и IndexedDB, не создавай дополнительную базу закладок.

### Приёмка / тесты F12

- `T01`: v3 round-trip: две категории, корневые ссылки, порядок, настройки, фон, favicon и thumbnails восстанавливаются.
- `T02`: два одинаковых URL в разных категориях с **разными эскизами** — после импорта изображения не перепутаны.
- `T03`: новый профиль/новые bookmark IDs — восстановлены новые реальные закладки и локальные картинки.
- `T04`: отсутствующий/некорректный исходный Blob → остальные данные экспортируются корректно, сбой явно отмечен.
- `T05`: неверная версия, огромный JSON, невалидный base64, SVG и опасный URL — отклонение **до любых мутаций**.
- `T06`: частичный отказ Bookmarks API/IndexedDB → честный отчёт о созданных записях, нет обещания атомарности.
- `T07`: пользователь отменил импорт → не создано/не изменено ничего.
- `T08`: экспорт не содержит профильных bookmark IDs, чувствительных данных, сторонних скриптов или тяжёлых логов.
- `T09`: повторный импорт может создать дубли, подтверждение об этом явно показано.
- `T10`: Chrome/Firefox: файл JSON открывается, скачивается, восстанавливает данные на чистом тестовом профиле, закрытие окна не ломает страницу.
- `T11`: в панели настроек ровно **одна** кнопка «Управление данными»; в едином окне есть все три действия, нет отдельных окон импорта/экспорта, ручного текста JSON и textarea.
- `T12`: нажатие «Экспорт» непосредственно запускает формирование/скачивание `.json` без промежуточного подтверждения; при ошибке сообщение в том же окне, повторный запуск безопасен.
- `T13`: импорт через выбор файла показывает его имя, количество элементов, настройки/изображения, целевую папку и предупреждение о дубликатах **до любых записей**; отмена и неверный JSON не меняют данные.
- `T14`: для импорта можно выбрать другую доступную папку назначения, в том числе среди одинаково названных; при отсутствии папки заблокирован только импорт.
- `T15`: сброс требует **встроенного** подтверждения и не использует `window.confirm()`/вложенный modal; отмена, Escape или закрытие окна ничего не сбрасывают.
- `T16`: сброс сохраняет настоящие закладки, категории, выбранную папку (включая F07 locator), сбрасывает параметры и очищает локальные изображения/фон; изменения sync-параметров могут быть получены другим устройством, но его локальные картинки не удаляются.
- `T17`: загрузка крупного файла/создание резервной копии/повторные нажатия/ошибки/частичный импорт не создают дубли из-за гонок; долгие действия имеют читаемые статусы.
- `T18`: Chrome/Firefox, светлая/тёмная тема и ширина 320–360 px: действия, встроенное подтверждение, ошибки и возвращение фокуса работают с мышью и клавиатурой без переполнения и потери доступности.

**Готово:** одно понятное место управления данными; экспорт напрямую скачивает JSON, импорт принимает только файл с проверкой и подтверждением в том же окне, сброс выполняется только после явного встроенного подтверждения; полная переносимость закладок, категорий, настроек и **растровых картинок** с сохранением связей после смены ID. Один коммит. **После F12 остановись, F13 не начинай.**

## F13 · P3 · Компактный виджет погоды

### Цель

Добавить **небольшой виджет погоды** на новую вкладку: он отображает **выбранный город** и позволяет одним нажатием открыть его прогноз на **Яндекс Погоде или Gismeteo**. Это именно компактный оформленный виджет, а не просто отдельная иконка или текстовая ссылка. **Часы не добавлять.** На этом этапе не требуются погодный API, ключи, сервер, геолокация и получение фактической температуры: нельзя изображать живой прогноз без источника данных.

### Требования

1. Разместить один компактный, визуально самостоятельный виджет в зоне второстепенных элементов новой вкладки. Показать узнаваемую нейтральную иконку погоды, **название выбранного города** и понятное действие перехода к прогнозу; сделать кликабельным весь виджет. Не создавать крупную панель, набор карточек или вторую строку инструментов, перекрывающую поиск, категории и почту.
2. В настройках предусмотреть простой выбор **города** и сервиса **Яндекс Погода / Gismeteo**; если город ещё не выбран, показывать ненавязчивое «Выберите город» без выдуманного местоположения и без запроса геолокации. Выбранные значения сохранять через действующий механизм автосохранения, в том числе Chrome Sync после F07, и восстанавливать между вкладками/устройствами. Не добавлять отдельную кнопку «Сохранить».
3. При нажатии открывать **страницу прогноза для выбранного города** на выбранном сервисе по корректному HTTPS URL. На реализации проверить действующий формат ссылок и способ сопоставления названия города со страницей сервиса; не строить URL из непроверенной транслитерации. При невозможности надёжно составить ссылку для города использовать безопасную страницу самого сервиса, не вести на чужой или ошибочный адрес и не притворяться, что открыта страница нужного города.
4. **Не показывать настоящую температуру, осадки, погодные условия, актуальные погодные иконки или прогноз**, пока не подключён достоверный источник погодных данных. Нейтральная декоративная иконка допустима, но не должна восприниматься как фактическая текущая погода. Не запрашивать погодный API, координаты, новые разрешения, не использовать таймеры обновления погоды и не внедрять сторонний скрипт информера.

Учитывать тему F11, токены оформления F06, контраст, hover/focus, доступность с клавиатуры, длинное название города и узкие экраны Chrome/Firefox. При отсутствии сети виджет остаётся ссылкой: не показывать вымышленные данные или ошибку «обновления прогноза».

**Файлы:** `App.vue`, `components/WeatherWidget.vue`, `components/SettingsPanel.vue`, `types/models.ts`, `services/settings.ts` и при необходимости небольшой модуль для безопасных ссылок.

## F14 · P2 · Mail.ru, Gmail и Яндекс Почта: компактные индикаторы

### Цель

Существующий `MailIndicator.vue` показывает Mail.ru. Доработать его в **одну общую функцию для трёх почтовых провайдеров**: Mail.ru, Gmail, Яндекс Почта. На новой вкладке показывать **только фирменные иконки и числовые бейджи**; в настройках — только параметры подключения/включения, **без счётчиков**.

### Отображение и взаимодействие

1. Для каждого включённого сервиса — **своя компактная иконка**, каждая кликабельна и ведёт на соответствующий веб-интерфейс почты. Не создавай большие виджеты, строки «У вас 10 писем», вкладки почтовых ящиков и новые диалоговые окна с сообщениями.
2. **Бейдж только если достоверное число непрочитанных > 0.** При нуле — бейджа нет. Если число неизвестно из-за ошибки/авторизации/недоступности API — **не показывай `0` как успешный ответ**, скрывай бейдж и объясняй статус в tooltip.
3. **Tooltip при нормальном результате показывает только название сервиса:** `Mail.ru`, `Gmail`, `Яндекс Почта`. **Не дублируй число непрочитанных** в tooltip: оно уже на бейдже. При `not authenticated` — `Войдите в Gmail/…`; при сетевой ошибке — отличное от «войдите» объяснение (`Не удалось проверить почту`); при unsupported — `Счётчик недоступен в этом браузере`.
4. Если включённый сервис не авторизован в данном профиле, **иконка остаётся**. Нажатие ведёт на страницу входа/почты обычным образом; не скрывай иконку только из-за отсутствия авторизации. Включение/выключение иконок — отдельные опции, а не зависимость от успешного счётчика.
5. В `SettingsPanel.vue`: для всех трёх сервисов переключатель `Показывать Mail.ru/Gmail/Яндекс Почту`; для Mail.ru сохрани текущий параметр email, если он требуется старому endpoint. В настройках **нет количества непрочитанных**, проверочной доски с email-письмами, вложений или самих писем.
6. Для существующих пользователей старый `email` Mail.ru не удалять и не терять. По умолчанию Mail.ru должен остаться видимым по прежней логике, Gmail и Яндекс Почта могут быть выключены, пока пользователь сам не включит их. Сохраняй настройки в WXT Storage; данные учётных записей, пароли, OAuth refresh-токены и cookies не сохраняй.

### Доступ к количеству непрочитанных (проверять реализуемость)

7. **Mail.ru:** использовать текущий проверенный механизм `unreadMail()` через сессию браузера; улучшить классификацию ошибок и tooltip, не менять произвольно URL/параметры.
8. **Gmail:** исследовать доступность счётчика с использованием **уже существующей авторизованной сессии** (например, исторический Gmail Atom Feed `https://mail.google.com/mail/feed/atom`, **только если в актуальных браузерах действительно работает**). Нельзя считать endpoint гарантированным, подменять ответ парсингом интерфейса/неофициальными обходами или выдавать непроверенный счётчик за настоящий. Потребность в cookie/CORS/permissions проверить на тестовом аккаунте. Если доступ не работает устойчиво, оставить включённую иконку и статус `Счётчик недоступен` вместо ложного числа.
9. **Яндекс Почта:** проверить легальный документированный или практически доступный механизм счётчика через обычную пользовательскую сессию. Не придумывать endpoint и не хранить пароль. Если браузерная политика/CORS/изменение сайта не позволяют получить точное количество — предоставить рабочую иконку и честный tooltip `Счётчик недоступен`, указать ограничение в отчёте, не делать скрытый scraping или стороннюю передачу cookies.
10. **Никаких новых OAuth-приложений/серверов/ключей** в рамках этой задачи без дополнительного согласования. Не используй доступ к письмам шире, чем нужен для счётчика; не выполняй fetch к несвязанным доменам. Само наличие прав `<all_urls>` в текущем manifest не повод читать произвольные сайты.
11. Запросы выполнять при открытии новой вкладки и после применения настроек; **не добавляй непрерывный polling** ради бейджей. Тайм-аут, отмена старых запросов, защита от гонок при переключении email/provider, независимые ошибки сервисов. Ошибка одного провайдера не влияет на два других и не ломает страницу.
12. Значения: целое неотрицательное число с ограничением отображения (например `99+` для крупных значений), только если backend действительно вернул валидное число. Строки с HTML/XML/JSON обрабатывать безопасным парсером и валидацией, без `innerHTML`. Не интерпретировать страницу входа/redirect/ошибку как 0.
13. Фирменные иконки разместить локально или безопасно в компоненте, без внешнего tracking CDN. Сохраняй размер и отступы, адаптивность верхней панели и сочетание с F11 (темой) и F13 (виджетом погоды).
14. Настройка почты не должна влиять на закладки, их синхронизацию, кэш изображений или экспорт изображений. Если `F12` уже реализована — настройки провайдеров входят в экспорт настроек, но **не** данные сессий.

**Файлы:** `components/MailIndicator.vue` (возможно переименовать в контейнер `MailIndicators.vue`), `components/SettingsPanel.vue`, `services/network.ts` (разнести провайдеров по чистым адаптерам при необходимости), `types/models.ts`, `services/validation.ts`, `App.vue`, `wxt.config.ts`/`manifest.json` — только при действительно необходимых разрешениях.
