# SPEC: Chrome Bookmarks как основа SpeedDial X

> **Адресат:** Codex, работающий в существующем репозитории [pawelermakov/speed-dial](https://github.com/pawelermakov/speed-dial), ветка `main`.
>
> **Статус:** новое исполняемое ТЗ. Перенос на WXT / Vue 3 / TypeScript / Tailwind CSS 4 **уже завершён**. Повторная миграция, `wxt init`, переписывание интерфейса с нуля и перенос данных старой Web SQL/IndexedDB-версии **не нужны**.
>
> **Главная цель:** заменить локальную базу закладок на стандартные закладки браузера с двусторонним редактированием и синхронизацией средствами Chrome. При этом сохранить работающие возможности расширения.
>
> **Приоритет:** сохранность закладок Chrome → корректность двусторонних изменений → работоспособность UI → локальное кэширование изображений → тесты и совместимость Chrome/Firefox → улучшения, не входящие в текущий объём.
>
> **Язык интерфейса и документации:** русский. Код, имена сущностей и Conventional Commits — на английском.

## 2. Целевая архитектура

Единственный источник истины для **закладок и категорий** — штатное дерево `browser.bookmarks` (через `wxt/browser`). Собственной параллельной структуры закладок/категорий в IndexedDB или `chrome.storage` быть не должно.

| Сущность | Источник истины | Локальные данные |
|---|---|---|
| URL и название закладки | Chrome/Firefox Bookmarks | Не дублировать как независимое хранилище |
| Категория и её название | Папка браузерных закладок | Не дублировать |
| Порядок закладок и категорий | Порядок детей папки в Bookmarks API | Не дублировать числовые позиции |
| Скриншот | Генерируется существующим механизмом | Blob в IndexedDB |
| Favicon | Favicon API/метаданные вкладки, когда доступно | Blob в IndexedDB |
| Пользовательский фон новой вкладки | Текущая настройка/локальный asset | Сохранить текущую возможность |
| Остальные настройки UI | Текущий механизм WXT Storage | Сохранить, не менять без необходимости |
| Выбранная корневая папка | Объект из Bookmarks API | Локальная ссылка/подсказка для повторного поиска |

**Удалить зависимость работающего списка закладок от таблицы `db.bookmarks`.** Не загружать на старте «свои» закладки из Dexie и не выполнять обратную запись всей коллекции после изменений. Техническая миграция схемы IndexedDB для освобождения таблиц допустима, но **импорт данных старой версии не нужен**. Не запускать старую миграцию `localStorage`/Web SQL и не восстанавливать старые данные автоматически.

Сохранять в IndexedDB **только воспроизводимые ресурсы плиток**, например по ключу `bookmarkId` + текущий нормализованный `url`, с `thumbnail`, `favicon` и временем обновления. Действующая пользовательская настройка фонового изображения — отдельная сущность, **не путать** её с пользовательским изображением плитки (таких изображений у плиток в новой версии нет).

## 3. Выделенная папка Speed Dial и категории

У расширения одна выбранная папка стандартных закладок, по умолчанию **Speed Dial**. Она находится **внутри** изменяемой стандартной папки браузера (например «Другие закладки»), а не прямо под недоступным для записи техническим корнем Bookmarks API.

Пример:

```text
Закладки браузера
└── Другие закладки
    ├── Speed Dial
    │   ├── Google
    │   ├── YouTube
    │   ├── Разработка
    │   │   ├── GitHub
    │   │   ├── MDN
    │   │   └── Документация
    │   │       └── Vue.js
    │   └── Работа
    │       └── GitLab
    └── Остальные закладки
```

**Правила отображения, обязательны:**

1. На начальном экране видны **только** прямые закладки выбранной папки Speed Dial или прямые закладки одной выбранной категории.
2. Категории — это **только прямые дочерние папки** Speed Dial, глубина `Speed Dial/Category`.
3. Прямые закладки Speed Dial относятся к **виртуальной** категории «Главная». Она не создаётся в браузере отдельной папкой.
4. Если в Speed Dial **нет дочерних папок**, отображай все её прямые закладки **без панели категорий**.
5. Если есть папки и хотя бы одна прямая закладка, покажи вкладки «Главная» и дочерних папок, «Главная» — первая.
6. Если есть только папки, **не показывай пустую «Главную»**; первоначально выбери первую доступную категорию.
7. При выборе категории показывай **только её непосредственные закладки**. Папки внутри категории и всё, что находится глубже, **игнорируй в UI** (без рекурсии, удаления и перемещения).
8. Пустая реальная категория видна и показывает аккуратное пустое состояние, позволяющее добавить в неё закладку.
9. Порядок реальных категорий и закладок — ровно порядок узлов от Bookmarks API. Виртуальная «Главная» всегда первая, если она показывается.
10. Если реальная папка названа «Главная», **не смешивай** её с виртуальной. Используй идентификаторы сущностей, а при визуальном совпадении надписей отличай реальную папку, не переименовывая её автоматически.
11. Глубже одного уровня категория не создаётся **самим расширением**. Существующие глубокие папки, созданные в Chrome, остаются нетронутыми.

Те же правила применяются, если пользователь выбрал **другую существующую папку** вместо Speed Dial. Нельзя читать и показывать всё дерево закладок Chrome по умолчанию.

## 4. Первоначальная настройка и поиск корневой папки

Сделай **надёжный и идемпотентный** выбор папки. Не предполагай, что `id` папок одинаков на разных устройствах: ID Bookmarks API — строка и гарантирован в пределах конкретного профиля, не между синхронизированными профилями.

Последовательность:

1. При запуске проверь сохранённый локальный `rootFolderId` через `bookmarks.get()`: это должна быть изменяемая папка. Если существует — используй её.
2. Если ID отсутствует/устарел, попробуй найти **однозначную** папку Speed Dial на основании структуры/расположения и сведений о хранилище аккаунта, когда они доступны.
3. Если одноимённых папок несколько, **не выбирать случайно**, не объединять содержимое: предложить пользователю выбрать нужную (покажи путь/расположение).
4. Если папки нет, предложить создать её либо выбрать существующую папку. Автосоздание разрешено только после проверки кандидатов, без риска второй одинаковой папки.
5. При создании в Chrome предпочитать доступную изменяемую папку аккаунта, когда это однозначно возможно. В новых Chrome могут сосуществовать синхронизируемые и локальные деревья; проверять `folderType`/`syncing` **как подсказку размещения**, а не как общий статус Chrome Sync. Если место неоднозначно — предложить выбор.
6. В Firefox и старых API без `syncing` не полагаться на это свойство; выбирать доступное место через API/диалог.
7. Смена выбранной папки в настройках **не копирует и не удаляет** закладки: немедленно переключает источник отображения. Сохраняй выбор локально. На втором профиле/устройстве восстановление выполняется по дереву закладок, а не по скопированному числовому/строковому ID.
8. Если выбранная папка удалена через менеджер Chrome, показывай понятное состояние повторного выбора/создания. **Не создавай новую папку молча** в ответ на событие удаления.
9. Невозможность получить доступ к Bookmarks API — явная ошибка с инструкцией, а не незаметный показ пустого списка.

Не использовать строковые названия локализованных служебных папок («Другие закладки» и т. п.) как единственный способ определения их роли. Не предполагать фиксированные корневые ID.

## 5. Модель данных и слои

Нужен ясный тонкий слой доступа к закладкам поверх `browser.bookmarks`, отдельный от локального кэша изображений и настроек.

Пример интерфейсов **как ориентир**, имена адаптировать к проекту:

```ts
type BookmarkId = string;

interface DialBookmark {
  id: BookmarkId;
  parentId: BookmarkId;
  url: string;
  title: string;
  index: number;
}

interface DialCategory {
  id: BookmarkId;
  title: string;
  index: number;
}

interface BookmarkAssets {
  bookmarkId: BookmarkId;
  url: string;
  thumbnail?: Blob;
  favicon?: Blob;
  thumbnailUpdatedAt?: number;
  faviconUpdatedAt?: number;
}
```

- Отдельно держать **структуру дерева/категорий**, **данные плитки с изображениями** и **настройки интерфейса**.
- Не переиспользовать старое `Bookmark.id: number`: Chrome/Firefox возвращают **строковые** ID. Обновить типы, ключи Vue, контекстное меню, drag-and-drop, тесты.
- У `BookmarkTreeNode` нет обязательного URL для папки. На уровне типизации не превращай папки в «закладки с пустым URL».
- Визуальный порядок получать из списка `children` / `index`, не сохранять `position`.
- Сервис закладок — единый адаптер чтения/создания/редактирования/удаления/переноса; сервис изображений — независимый CRUD по IndexedDB.
- Существующий `useDial` допускается разделить на небольшие composable/service; не создавать монолитного нового класса и не плодить слои ради абстракций.
- `navigator.locks` и `BroadcastChannel` можно использовать там, где они оправданы для собственных операций, но они **не заменяют события закладок браузера** и не сериализуют внешний менеджер Chrome.
- События браузера и локальные действия должны сводиться к одному актуальному представлению, без «последняя локальная копия победила».

## 6. Двусторонние операции и синхронность UI

Все операции над закладками/папками в расширении выполняй **через Bookmarks API**, а не через запись локального снапшота.

### 6.1 Закладки

- Добавление: использовать текущую категорию; для «Главной» — непосредственно выбранную корневую папку. По умолчанию сохранять корректный URL и название (метаданные страницы, если доступны; иначе hostname), без обязанности успешно сгенерировать скриншот.
- Редактирование: через `bookmarks.update(id, {title, url})` с проверками существования и текущего расположения; не изменять чужую закладку из другой папки.
- Удаление: `bookmarks.remove(id)` после подтверждения, поскольку это **реальное** удаление браузерной закладки, которое может синхронизироваться на другие устройства.
- Перестановка внутри категории: `bookmarks.move(id, {parentId, index})`. После успешной операции перечитывать реальный порядок, не пытаться записывать весь массив независимыми «позициями».
- Перенос между «Главной» и реальными категориями: менять `parentId` с помощью `bookmarks.move()`. Предусмотреть понятный выбор категории (в форме редактирования и/или перетаскиванием на вкладку). Не допускать перемещения за пределы выбранного поддерева.
- Drag & Drop должен сохранять прежнее поведение сортировки; отмена, неверный target и ошибка API не приводят к потере элемента. При одновременных изменениях — перечитать и показать актуальное состояние.

### 6.2 Категории

- Минимальное управление внутри расширения: **создать, переименовать, удалить и переставить** папку-категорию первого уровня. Использовать `bookmarks.create/update/move/removeTree` по назначению.
- Создавать категории только под выбранной корневой папкой. Реальные папки Chrome можно переименовывать и перемещать через менеджер закладок — UI должен это отражать.
- Перед удалением категории **явно** предупреждать, что будет удалена реальная папка Chrome и все её потомки, включая те, которые Speed Dial не показывает. Защита от случайного удаления важнее однокликового UX. Не вызывай `removeTree` для служебных/выбранной корневой папки.
- Если категория исчезла извне, переключиться на «Главную» при её наличии, иначе на первую категорию или корректное пустое состояние. Не хранить неизменяемое состояние активной категории после удаления.
- При внешнем переносе категории из Speed Dial она должна **исчезнуть из интерфейса без удаления**.
- Порядок вкладок категорий соответствует Chrome; только виртуальная «Главная» закреплена первой.

### 6.3 События и параллельные изменения

Подписываться на подходящие события `bookmarks.onCreated`, `onRemoved`, `onChanged`, `onMoved`, `onChildrenReordered` (если доступно), `onImportBegan/onImportEnded` (при наличии/необходимости). Реагировать и на изменения через штатный менеджер Chrome, и на синхронизацию, и на несколько открытых новых вкладок.

- Обновлять затронутое представление без полной перезагрузки вкладки. Разрешается простое перечитывание выбранной ветви дерева с debounce/coalescing событий вместо сложных инкрементальных патчей.
- Избегать гонок: устаревшее асинхронное чтение не должно затереть более новое; use generation/sequence или эквивалент.
- При ошибке мутации откатить оптимистичное UI (если есть) и перечитать данные.
- При нескольких событиях одного перемещения не запускать бесконечный цикл обновлений.
- Корректно отписываться от слушателей при размонтировании.
- При внешней смене URL закладки сбрасывать **привязку** старых локальных изображений; при смене названия или категории без смены URL изображения остаются.
- Изменения, приходящие на другом устройстве, отображаются **после того, как Chrome доставит их через свою синхронизацию**. Не обещать мгновенную облачную доставку.

## 7. Favicon и скриншоты: независимый локальный кэш

**Сохрани существующий рабочий захват скриншота отдельной плитки** через background/временную вкладку. Не реализовывай массовую генерацию изображений категории. Пользовательских изображений для **плиток** нет, добавлять загрузку собственного изображения плитки не нужно.

### 7.1 Хранение

- Сделать Dexie-схему для `BookmarkAssets`. Каждый ресурс привязан к строковому ID закладки **и URL**, чтобы старые изображения не показывались после изменения адреса.
- Favicon и скриншот хранить как локальные Blob (с разумной валидацией MIME, размера и формата) и временем успешного обновления. Допустимо физически хранить отдельно, если API остаётся простым.
- Не переносить изображения через Chrome Bookmarks, `chrome.storage.sync` или собственное облако; не сохранять их в названии или URL закладки.
- Хранить фон новой вкладки отдельно, не удалять его при очистке устаревших ресурсов плиток.
- Изображения должны быть **необязательными**: отсутствие/повреждение IndexedDB или отдельного Blob не делает закладки недоступными.
- При удалении/перемещении закладки не путать её отсутствие в выбранной папке с удалением из браузера. **Нельзя очищать кэш при простом переносе** в другую категорию или за пределы Speed Dial, если браузерная закладка продолжает существовать; безопасная очистка возможна после подтверждённого удаления либо отдельной операции уборки кэша.

### 7.2 Получение и обновление

- При отображении, если favicon нет локально, пробовать получить его из доступного механизма браузера; **не блокировать UI** и не требовать посещения сайта ради одной иконки.
- В Chrome возможно использование `/_favicon/` с `favicon` permission. В Firefox проверить поддерживаемый способ (например, метаданные открытой вкладки); при отсутствии не делать ложное предположение о совместимости Chrome-specific URL.
- Если API не знает favicon, допускается безопасная заглушка с названием/инициалом сайта. Не кешировать заглушку как настоящую иконку.
- При существующем действии «Обновить эскиз» попытаться **обновить и favicon**. Сохранение/ошибка каждого ресурса независимы: успех скриншота нельзя отменять только из-за ошибки иконки и наоборот.
- Если захват возвращает `title`, он **не должен затирать вручную отредактированное название** закладки; менять название только действием редактирования или при первоначальном создании, если имя не задано.
- Асинхронное обновление не сохраняет ресурс для удалённой/изменённой закладки: перед записью повторно сверять ID, URL и существование через Bookmarks API.
- Не записывать и не отображать небезопасные `javascript:`, `data:` или произвольный SVG/HTML как favicon. Следовать текущей валидации URL и изображений.
- Не вводить сторонний сервис favicon или передачу полных URL третьим лицам **как новый обязательный механизм**. Если в текущем захвате есть внешний fallback, оценить приватность и оставить его только как явно обоснованный безопасный fallback.
- Для Blob использовать `URL.createObjectURL()` с обязательным `URL.revokeObjectURL()` при смене данных/размонтировании; избегать постоянных base64-строк в реактивном состоянии.

### 7.3 Отрисовка

- Сохранять существующую визуальную сетку, карточки и режимы.
- Если есть скриншот — показывать его как фон/превью плитки; favicon отображается в заголовке, когда есть.
- Если скриншота нет — плитка **всё равно сразу доступна**: favicon (если есть) и/или нейтральная заглушка плюс видимое название.
- При первом запуске на новом устройстве закладки и папки отображаются до восстановления изображений; автоматическое получение отсутствующих favicon — неблокирующее. **Массовые скриншоты не генерировать**.
- Пустой кэш, повторный запуск, недоступность сайта и сбой захвата не разрушают модель закладок.

## 8. Общий статус Chrome Sync в настройках

Пользователь хочет видеть **общий статус синхронизации профиля Google Chrome**, а **не статус `syncing` конкретной папки/закладки**.

В Chrome использовать поддерживаемый API `chrome.identity.getProfileUserInfo({accountStatus: 'SYNC'})`: наличие непустого `id` означает, что для основного аккаунта профиля включён Chrome Sync. Для этого может потребоваться `identity.email` в manifest; **не сохранять и не показывать email и ID аккаунта**. Не запрашивать OAuth-токены и не создавать авторизацию внутри Speed Dial. Проверить фактическое поведение/разрешения в тестовой сборке, а не полагаться только на типы.

Показывать в `SettingsPanel.vue` компактный индикатор:

- **Включена** — Chrome сообщает об активном Sync для основного профиля.
- **Выключена** — по достоверным данным Sync отсутствует; текст «Включите синхронизацию Chrome, чтобы закладки были доступны на других устройствах».
- **Не удалось определить** — API недоступен, нет разрешения, произошла ошибка либо состояние не подтверждено. Не приравнивать к «Выключена».
- **Firefox:** не называть Sync «выключенной» по отсутствию Chrome Identity API. Либо предоставить обоснованную специфичную Firefox-проверку, либо показать «Статус синхронизации недоступен в Firefox» с инструкцией проверить настройки браузера.

Обновлять статус при открытии панели настроек (при необходимости ещё при возврате фокуса), без фонового polling. Можно дать переход к настройкам синхронизации **при поддержке браузером**, с безопасным текстовым fallback.

**Чётко сообщить ограничение:** `SYNC` не подтверждает, что отдельная настройка синхронизации **закладок** включена или что все изменения уже доставлены на сервер. Свойство `BookmarkTreeNode.syncing` используется для выбора места хранения папки (§4), **не вместо общего индикатора**.

## 9. Импорт, экспорт, удаление данных и совместимость имеющегося UI

Поскольку нынешний интерфейс содержит импорт/экспорт и сброс, **не оставлять эти кнопки привязанными к старой `db.bookmarks`**. Их поведение необходимо адаптировать и протестировать.

- **Экспорт**: сериализовать текущее выбранное поддерево Speed Dial (прямые закладки и категории первого уровня с прямыми закладками) в понятный версионированный JSON. Сохранить поддерживаемый экспорт настроек и пользовательского фона, если он есть. Не экспортировать скриншоты и favicon: это воспроизводимый локальный кэш.
- **Импорт**: валидировать JSON **до** изменений, включая URL, объём и структуру; поддержать формат нового экспорта. Импортировать **только в выбранную папку**; не изменять остальные закладки Chrome. Для первой версии — безопасное **добавление**, с явным предупреждением о возможных дубликатах; не выполнять молчаливую замену/удаление существующих данных. Если случился частичный сбой Bookmarks API, показать точный результат и не заявлять об атомарности, которой у API нет. Не создавать папки глубже первого уровня.
- **Старый Web SQL/legacy JSON импорт и автоматическая миграция**: специально реализовывать совместимость не нужно. Старый код импорта, связанный с прежним форматом `tabs`/числовыми ID, допускается удалить. Не оставлять старый импорт, который подменяет локальные закладки, как якобы рабочий.
- **Сброс/«Удалить все данные»**: не удалять вообще все закладки профиля браузера. Переработать название и подтверждение, чётко отделить сброс настроек/локального кэша от удаления закладок выбранной папки. Если предусмотрена очистка Speed Dial, она требует **отдельного явно описанного подтверждения**, указывающего на реальное удаление и потенциальную синхронизацию. Невидимые вложенные папки не должны удаляться незаметно: при их наличии блокировать массовую очистку и направлять в менеджер закладок либо запрашивать специальное отдельное предупреждение о них.
- Сохранить поиск Яндекса, Mail.ru, настройки сетки, пользовательский фон, контекстное меню, доступность клавиатурой и остальное поведение текущей WXT-версии. Не превращать текущую задачу в новый редизайн.
- Если отдельная прежняя возможность принципиально не согласуется с новым источником данных, выбрать **явную безопасную семантику**, покрыть тестом и указать изменение в отчёте.

## 10. Манифесты, Chrome и Firefox

Обновить `manifest.json`/`wxt.config.ts` с учётом фактической схемы генерации манифестов WXT:

- Включить **`bookmarks` permission** для Chrome и Firefox.
- Для Chrome favicon API добавить **`favicon` permission** только если реализован этот путь; проверить фактическую работу Chrome MV3.
- Для проверки статуса общего Chrome Sync добавить **`identity.email`** (и иные реально обязательные разрешения только если API их требует), по возможности **только в Chrome-сборку**. Не запрашивать OAuth scopes.
- Не удалять существующие разрешения `tabs`/`<all_urls>` без аудита текущего захвата скриншотов/сети: существующие действия должны продолжать работать.
- Отдельно проверить манифесты в `.output/chrome-mv3` и `.output/firefox-mv2`; не считать сходство типов гарантией работы в обоих браузерах.
- При отсутствии API/разрешения — явная ошибка/деградация **соответствующей необязательной функции**, а не падение всей новой вкладки.
- Не отправлять дерево закладок, названия, URL, локальные картинки или идентификатор Google-аккаунта на сторонние сервера расширения; собственного сервера/аккаунта/облачной синхронизации не создавать.

## 12. Автоматические тесты — обязательные сценарии

Использовать Vitest и существующие тесты, дополнив моками Bookmarks API, IndexedDB (при необходимости `fake-indexeddb`) и интерфейсных операций. Тесты не должны модифицировать реальные закладки пользователя.

### 12.1 Папка и дерево

- Нет папки Speed Dial → корректный выбор/создание без дублей.
- Есть ровно одна подходящая папка → найдена после установки.
- Одноимённые папки → явный выбор, без случайного объединения.
- Сохранённый ID устарел на другом устройстве → повторный поиск, корректный выбор.
- Отдельные локальная и аккаунтная ветви Chrome → предпочтение правильной ветви либо запрос выбора.
- Недоступное/управляемое дерево → ошибка без порчи данных.
- Нет категорий; смешанная папка; только категории; полностью пустая папка.
- Прямая закладка виртуальной «Главной»; пустая реальная категория.
- Вложенность `Speed Dial/Category/Folder/Bookmark` не попадает в UI и не меняется.
- Совпадение названия реальной папки с «Главной» не объединяет разные категории.
- Переключение основной папки не копирует и не удаляет старые закладки.

### 12.2 Действия и внешние изменения

- Добавить/редактировать URL и название/удалить закладку в «Главной» и реальной категории.
- Создать/переименовать/переместить/удалить категорию; подтвердить опасное удаление.
- Сортировка в начало/середину/конец, отмена DnD, перенос между категориями.
- API `move` падает посередине операции → UI перечитывает фактический порядок.
- Внешний `onCreated/onChanged/onRemoved/onMoved` обновляет открытый Speed Dial.
- Переименование извне сохраняет favicon/скриншот.
- Изменение URL извне не показывает старые изображения.
- Удаление активной категории, выбранной корневой папки, перенос категории за пределы Speed Dial.
- Серия быстрых событий и медленные асинхронные ответы не возвращают устаревшие данные.
- Две открытые вкладки новой страницы получают согласованное отображение.

### 12.3 Картинки и синхронизация

- Пустая/очищенная IndexedDB → все закладки доступны по URL, заголовки читаемы.
- Нет favicon → безопасная заглушка; favicon появился позже → сохранён локально.
- Скриншот обновился, favicon не удалось получить → скриншот сохранён.
- Favicon обновился, скриншот получить не удалось → favicon сохранён.
- Во время захвата URL изменён/закладка удалена → устаревшие ресурсы не сохраняются.
- Передвижение закладки между категориями не удаляет её активный кэш.
- При захвате не затирается вручную заданное название.
- Состояния статуса Chrome Sync: включён/выключен/API отказал/Firefox unsupported.
- Индикатор общего Chrome Sync не строится на `BookmarkTreeNode.syncing`.
- Никакой автоматической массовой генерации скриншотов.

### 12.4 Старые действия UI, но новый источник

- Импорт/экспорт нового формата с категориями и порядком.
- Неверный JSON/опасный URL ничего не меняет в браузерных закладках.
- Импорт затрагивает только выбранную папку; другие папки браузера не меняются.
- Сбой посередине импорта честно отражён, нет сообщения о полном успехе.
- Сброс настроек не удаляет браузерные закладки.
- Явная очистка Speed Dial не удаляет чужие папки и не скрывает риск удаления вложенных элементов.
- Поиск, Mail.ru, фон, сетка, контекстные меню, открытие в новой вкладке и обновление одиночного эскиза продолжают работать.

## 13. Ручная проверка в реальном браузере

Одних unit-тестов недостаточно. Провести проверку в **тестовом профиле браузера**, а не на настоящих пользовательских закладках.

**Chrome (обязательно):**

1. Чистый профиль/пустой Speed Dial: создать папку и 2–3 закладки, перезапустить браузер.
2. Добавить/переименовать/переставить/удалить через Speed Dial → увидеть те же изменения в штатном менеджере Chrome.
3. Повторить изменения через менеджер Chrome → **без перезагрузки новой вкладки** увидеть изменения в расширении.
4. Создать 2 категории, одну прямую закладку, глубокую вложенную папку; проверить правила «Главной», категории и невидимости глубоких элементов.
5. Проверить смену категории и перенос закладок, DnD и сохранение порядка после перезапуска.
6. Проверить favicon/скриншот, потерю IndexedDB и воспроизводимость изображений; открытие ссылок без картинок.
7. Проверить статус общего Sync как минимум во включённом и выключенном состоянии (в тестовом профиле).
8. Если доступна пара синхронизируемых тестовых профилей/устройств: убедиться, что после доставки штатной синхронизации Chrome совпадают названия, папки, порядок и URL; картинки при этом могут отсутствовать на новом устройстве.
9. Проверить, что **ни одна операция** расширения не меняет закладки за пределами выбранной папки.

**Firefox (обязательно, раз сборка поддерживается):**

1. Установка и запуск Firefox-сборки с `bookmarks` permission.
2. CRUD категорий/плиток и изменение через штатный менеджер закладок.
3. Скриншот отдельной плитки и безопасная деградация favicon.
4. Вместо ложного «Sync выключена» — корректный неподдерживаемый статус или проверенная Firefox-реализация.

Если нет доступа к определённому реальному сценарию, **не заявлять его проверенным**: записать непроверенное в итоговом отчёте вместе с инструкцией, как его воспроизвести.

## 14. Definition of Done (критерии приёмки)

Работа завершена, только если **все** условия выполнены:

1. Основной источник закладок и категорий — Bookmarks API. Удаление/очистка IndexedDB не приводит к потере списка закладок.
2. Speed Dial показывает содержимое **одной выбранной папки** и соблюдает правила одного уровня категорий и виртуальной «Главной».
3. Добавление, редактирование, удаление, DnD, перенос и переименование в расширении изменяют стандартные закладки браузера.
4. Изменение через менеджер браузера корректно отражается в открытом Speed Dial.
5. Чужие закладки, глубокие вложенные папки и служебные папки браузера защищены от случайных действий расширения.
6. Локальные скриншоты и favicon не участвуют в облачной синхронизации; работоспособность без них полная.
7. Отдельная генерация/обновление скриншота сохранена; при обновлении запрашивается также favicon без жёсткой зависимости между ними.
8. В настройках отображается **общий** статус Chrome Sync с корректным состоянием «неизвестно»; Firefox не получает ложный статус.
9. Импорт, экспорт и сброс адаптированы к Chrome Bookmarks и не способны молча уничтожить всё дерево браузера.
10. Не потеряны поиск Яндекса, Mail.ru, фон, сетка и существующие UI-функции.
11. Проверены `npm run compile`, `npm test`, `npm run build`, `npm run build:firefox`; при наличии подходящей среды — smoke/браузерные сценарии. Не скрывать реальные FAIL.
12. `README.md` отражает **новую** архитектуру; старые инструкции по переносу Web SQL не выдаются за текущую задачу.
13. Код минимален и понятен; нет двух источников истины для закладок и неиспользуемых legacy-путей.
14. Изменения продемонстрированы тестами, а итоговый отчёт перечисляет фактически проверенные сценарии и ограничения.

**По завершении**: дай отчёт «что изменено → какие тесты прошли/не прошли → что проверено вручную → ограничения → следующие необязательные улучшения». Предложи Conventional Commit на английском **без scope**, например `feat: use browser bookmarks as dial source`. Не выполняй `git push`, не создавай релиз или тег без отдельного разрешения пользователя.

## 15. Вне объёма этой задачи

**Не делать сейчас**: миграцию старой Web SQL/IndexedDB-базы закладок, автоматическое восстановление legacy JSON, повторный перенос на WXT, вторую параллельную систему папок, рекурсивное отображение папок глубже одного уровня, массовую генерацию эскизов, пользовательские изображения плиток, собственную синхронизацию/сервер/логин, многоуровневую навигацию, редизайн, новый поисковик, дополнительные виджеты, новые категории данных и искусственные UX-удобства, которые не нужны для замены источника закладок.

**Порядок дальнейшей разработки:** сначала добиться надёжного завершения этой спецификации (это фундамент архитектуры). Только затем добавлять необязательные функции удобства.
