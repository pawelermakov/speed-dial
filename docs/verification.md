## Найденные и исправленные ошибки

- Для `getProfileUserInfo` в реальном Chrome одного `identity.email` оказалось недостаточно: без `identity` namespace отсутствовал. Обе permissions добавлены только в Chrome.
- Chrome `/_favicon/` возвращает валидный PNG с пустым MIME. После проверки PNG-сигнатуры ресурс получает `image/png`; штатная заглушка сравнивается с ответом для заведомо неизвестного `.invalid` URL и не кэшируется как favicon сайта. Этот URL обрабатывается локальным API; сайт не открывается.
- Перенос последней прямой закладки убирает виртуальную «Главную» и переключает на первую папку, поэтому smoke проверяет соответствующий fallback.
- DnD категории: `dragend` очищал реактивный ID до выполнения операции внутри Web Lock. ID теперь захватывается в локальную переменную до ожидания; реальный браузерный тест проверяет порядок.
- В тестах ожидание завершения закрытия модального окна необходимо до следующего действия с клавиатурой.

## Визуальный просмотр и ограничения ручной проверки

Просмотрены PNG новых окон настроек, добавления и редактирования; названия и выбор категории читаемы. Полноценная ручная работа мышью в штатных менеджерах Chrome/Firefox не выполнена: внешние изменения в smoke вызываются штатным Bookmarks API из тестового профиля и проверяются в живом интерфейсе расширения.

Не подтверждены на реальных аккаунтах: Sync **включена**, доставка между двумя синхронизированными устройствами, сосуществование аккаунтной и локальной ветвей, корпоративная политика, личный счётчик Mail.ru. Включённый/неизвестный Sync и структуры деревьев проверены моками; реальный чистый Chrome подтверждает выключенный Sync. Не выдавать это за проверку облачной доставки. У Bookmarks API нет транзакций: внешнее перемещение в узком интервале между проверкой узла и мутацией нельзя атомарно заблокировать; операции повторно сверяют принадлежность и перечитывают актуальное дерево.

Воспроизведение оставшихся ручных сценариев: используйте тестовый профиль, включите Sync и синхронизацию закладок, создайте 2 категории и глубокую папку; повторите CRUD и перестановку в штатном менеджере при открытой новой вкладке; перезапустите браузер. На втором тестовом устройстве дождитесь штатной доставки и сравните URL/названия/порядок. Изображения на втором устройстве могут отсутствовать. Для Firefox повторите действия в «Библиотеке» и проверьте отсутствие ложного статуса «Sync выключена».

Необязательное продолжение: расширить ручную матрицу на аккаунтные деревья и два устройства, утвердить отдельные эталоны для новых окон. Новых продуктовых функций для завершения текущей модели не требуется.

## F01 — текстовые плитки: итоговая проверка, 17 октября 2026

Без рабочего эскиза показывается однострочный домен на фоне основного цвета favicon. Для всех сайтов применяется один порог относительной яркости 0,12: светлые цвета затемняются, тёмные остаются исходными. Если иконка отсутствует или повреждена, используется детерминированный цвет домена. Текст белый с лёгкой тенью; размер и усечение адаптируются к карточке.

Цвет хранится вместе с локальной иконкой и её версией алгоритма. Временный сбой декодирования не сохраняется как окончательная ошибка и допускает повторную попытку. Валидные эскизы и object URL сохраняются при переименовании, сортировке и повторном чтении IndexedDB; при смене URL или версии изображения старый ресурс освобождается. При полной перезагрузке сетка показывается после декодирования локальных эскизов: промежуточные текстовые карточки скрыты, а геометрия сетки сохраняется. Настоящие закладки и формат экспорта не изменены.

Сетка уменьшает число колонок по фактической ширине контейнера: целевая минимальная ширина карточки 140 px, сохранённое число колонок — верхний предел. Ширина, интервалы, радиус и оформление карточек с эскизами сохраняются.

- PASS: TypeScript, unit-тесты и production-сборки Chrome MV3 / Firefox MV2.
- PASS: `npm run test:tiles` — все текстовые плитки сохраняют цвет по кадрам; при полной перезагрузке с искусственной задержкой декодирования 100 мс и при переименовании эскиз не переключается в текстовый режим; реальные ICO Яндекса/YouTube; миграция кэша; 360/1280/1920 × 2/6/12 колонок с проверкой видимого размера карточек.

## F02 — выбор папки в настройках, 17 октября 2026

Вместо отдельного FolderDialog и поиска/создания Speed Dial настройки содержат native select с полными путями доступных папок. Новый профиль использует однозначно определённую системную «Другие закладки»; действующий выбор сохраняется. При удалении источника выбирается доступная «Другие закладки» с уведомлением, при неоднозначности предлагается ручной выбор. Управляемые ветви и технический корень исключены. Chrome определяется по метаданным API, Firefox — по проверенной структуре системных GUID; названия и числовые Chrome ID для определения источника не используются.

Выбор применяется только при сохранении; отмена оставляет источник прежним. Список обновляется при внешних изменениях, сохраняя черновик. Ошибки чтения и записи показаны в настройках; при ошибке сохранения прежний источник сохраняется, уже записанные настройки восстанавливаются. Переключение не изменяет закладки, изображения или остальные настройки; открытые вкладки принимают новый источник. Массовая очистка и её методы удалены. Отдельное удаление закладки/категории и сброс настроек/кэша сохранены. Импорт подтверждает путь текущего источника; JSON v2 не изменён.

- PASS: TypeScript; 91 unit-тест в 10 файлах; production-сборки Chrome MV3 и Firefox MV2.
- PASS: Chrome/Firefox smoke — системный источник нового профиля, сохранение через select, CRUD и захват, безопасный сброс, восстановление после удаления источника. Chrome дополнительно проверяет отмену, A → B → A с сохранением изображений, две вкладки, внешнее переименование, ошибки API/Storage и отсутствие мутаций при выборе.
- PASS: визуальная проверка 300+ папок, длинных путей и удаления выбранного черновика на 360/1280/1920 px; горизонтального переполнения нет. Новые PNG просмотрены, прежние эталоны не перезаписаны.
- PASS: регрессия текстовых плиток F01 и прежних неизменённых экранов.

Проверки используют отдельные профили и тестовые закладки. Реальные аккаунтные/локальные деревья Chrome вместе, корпоративные политики и доставка Sync между устройствами вручную не проверены; соответствующие структуры и неоднозначность выбора покрыты unit-тестами. Транзакций между Storage и IndexedDB нет: ошибки компенсируются восстановлением, отдельное сообщение сообщает о неудаче самого восстановления.

Правила API сверены с [Chrome Bookmarks API](https://developer.chrome.com/docs/extensions/reference/api/bookmarks), [описанием нескольких деревьев Chrome](https://developer.chrome.com/blog/bookmarks-sync-changes) и [MDN getTree](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/bookmarks/getTree). Структура Firefox дополнительно проверена в изолированном браузере.
