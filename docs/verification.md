## Найденные и исправленные ошибки

- Для `getProfileUserInfo` в реальном Chrome одного `identity.email` оказалось недостаточно: без `identity` namespace отсутствовал. Обе permissions добавлены только в Chrome.
- Chrome `/_favicon/` возвращает валидный PNG с пустым MIME. После проверки PNG-сигнатуры ресурс получает `image/png`; штатная заглушка сравнивается с ответом для заведомо неизвестного `.invalid` URL и не кэшируется как favicon сайта. Этот URL обрабатывается локальным API; сайт не открывается.
- Перенос последней прямой закладки убирает виртуальную «Главную» и переключает на первую папку, поэтому smoke проверяет соответствующий fallback.
- DnD категории: `dragend` очищал реактивный ID до выполнения операции внутри Web Lock. ID теперь захватывается в локальную переменную до ожидания; реальный браузерный тест проверяет порядок.
- В тестах ожидание завершения закрытия модального окна необходимо до следующего действия с клавиатурой.

Просмотрены PNG новых окон настроек, добавления и редактирования; названия и выбор категории читаемы. Включённый/неизвестный Sync и структуры деревьев проверены моками; реальный чистый Chrome подтверждает выключенный Sync. Не выдавать это за проверку облачной доставки. У Bookmarks API нет транзакций: внешнее перемещение в узком интервале между проверкой узла и мутацией нельзя атомарно заблокировать; операции повторно сверяют принадлежность и перечитывают актуальное дерево.

Воспроизведение оставшихся ручных сценариев: используйте тестовый профиль, включите Sync и синхронизацию закладок, создайте 2 категории и глубокую папку; повторите CRUD и перестановку в штатном менеджере при открытой новой вкладке; перезапустите браузер. На втором тестовом устройстве дождитесь штатной доставки и сравните URL/названия/порядок. Изображения на втором устройстве могут отсутствовать. Для Firefox повторите действия в «Библиотеке» и проверьте отсутствие ложного статуса «Sync выключена».

Необязательное продолжение: расширить ручную матрицу на аккаунтные деревья и два устройства, утвердить отдельные эталоны для новых окон. Новых продуктовых функций для завершения текущей модели не требуется.

## F05 — настройки и плавное переключение, выполнена 18 октября 2026

**Поведение:** общая кнопка сохранения и общий draft убраны. Checkbox/select сразу обновляют одно поле, числовые поля и email используют валидируемый буфер 275 мс с flush на change/blur/закрытие. Перед импортом, экспортом и сбросом завершаются ожидающие записи. Поля записываются patch-операциями под общим data lock из актуального Storage; searchProvider использует тот же механизм. Storage.watch отражает подтверждённые изменения других вкладок, pending-поля сохраняют более поздний ввод. При ошибке откатывается только последнее неудачное поле, сообщение с его названием остаётся доступным после закрытия. Панель сгруппирована, кнопка закрытия и «Удалить фон» видимы. Действующие настройки, источник и JSON v2 сохранены; параметры оформления F06 не добавлялись.

**Причина мерцания проверена до изменения:** в чистом Chromium с пользовательским фоном выбор категории изменял background-image с одного blob URL на другой при том же изображении. Repository.load теперь читает фон только при первоначальной загрузке/его изменении; favicon, категории и источники не требуют повторного чтения фонового Blob.
