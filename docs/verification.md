## Намеренные изменения

- Web SQL заменён IndexedDB. Историческая Web SQL БД не эмулируется и не обещается её автоматическое восстановление.
- Небольшие настройки используют локальный WXT Storage; фон и снимки — Blob в IDB.
- Старые `"false"`/пустые значения разбираются корректно; сохранение не вызывает `localStorage.clear()`.
- Импорт сначала проверяется, затем подтверждается и заменяет набор одной IDB-транзакцией. Snapshot и журнал обеспечивают восстановление при отказе второго хранилища/прерывании процесса.
- Весь недоверенный текст выводится Vue-интерполяцией, разрешены только HTTP/HTTPS URL без embedded credentials; SVG/data/javascript/file ссылки не становятся ссылками карточек.
- Скриншоты сериализованы, содержат request ID, проверку активности/URL до и после захвата, отмену, cleanup и timeout. Firefox about:blank до начала HTTP-навигации не считается готовым сайтом.
- При изменении URL старые favicon/эскиз сбрасываются, чтобы не показывать другой сайт. Для нового адреса доступно явное обновление эскиза.
- JPEG quality 80 вместо исходного PNG уменьшает размер; IDB хранит Blob. При отказе обновления предыдущий снимок не стирается, пользовательский title сохраняется.
- Поиск и endpoints Яндекса/Mail.ru сохранены. Добавлены debounce, AbortController, защита от устаревших ответов, ошибки и отсутствие ложного бейджа.
- Экспорт сохраняет совместимый tabs/settings, исключает эскизы как раньше, включает фон и не мутирует исходные карточки.
- Firefox MV2 генерируется WXT, Chrome — MV3. Нет popup/options/content scripts. Firefox 140+ имеет декларацию передачи поисковых запросов, email и адресов сайтов.

Chrome: Playwright запускает реальное unpacked-расширение, проверяет настоящий screenshot API, два быстрых захвата, точное соответствие ответов и сохранение остальных ID вкладок. Ошибок pageerror в тесте нет.

Firefox: Playwright-драйвер зависает при moz-extension-навигации. Для проверки используется штатный Marionette/WebDriver с Addon:Install: **само расширение и его browser API не замоканы**. Пройдены screenshot API, парная очередь, cleanup, title-preserving refresh, timeout/fallback, CRUD, reorder/reload, JSON-import, настройки/фон, export и повторное открытие с тем же профилем. DnD последовательность передаётся DOM DragEvent/DataTransfer; жест настоящей мышью Firefox остаётся пунктом ручной проверки.

Chrome layout: реальные viewport 360×800, 1280×800, 1920×1080. Firefox: 1280/1920 в native window; точный 360×800 проверен в same-origin iframe, поскольку headless Firefox на Windows ограничивает минимальную ширину окна 500 px. Проверены innerWidth/innerHeight, отсутствие overflow и отдельный screenshot iframe. PNG просмотрены; видны настоящие жёлтые страницы тестового HTTP-сайта в карточках, а не чужая новая вкладка.

Яндекс: оба расширения получают HTTP 200 и 10 реальных подсказок по публичному тестовому запросу. Стрелки/Escape UI проверены в Chrome с детерминированными ответами. Прежний yandsearch endpoint возвращает HTTP 200, но может показывать CAPTCHA.

Mail.ru: в обоих чистых профилях HTTP 200, JSON `{"status":"noauth",...}`. Это не нулевой счётчик. Chrome UI проверен с синтетическими ответами 3/0/noauth и пустым email; повторное сохранение того же email повторяет проверку. Ненулевой **живой** счётчик личного аккаунта не подтверждён: личные cookies/email не использовались.

Сырые результаты и изображения оставлены в игнорируемой `.browser-test/`. Fixtures используют example.com/example.org/example.invalid и не содержат личных данных.

## Неподтверждённые сценарии и ограничения

- Авторизованная почта с настоящим ненулевым счётчиком, SameSite/Firefox cookie containers и политики личного профиля.
- Ручные browser button «+», жесты DnD Firefox, клавиатурные/мышиные сценарии списка Яндекса Firefox, произвольные HTTPS-сайты/SPA/редиректы/закрытие окна пользователем в ходе capture.
- Принудительное уничтожение фонового процесса/браузера ОС может оставить временную вкладку: finally тогда не исполняется. Новая сессия не закрывает вкладки по старым IDs.
- Постоянная Firefox установка/подпись и Chrome Store публикация не выполнялись и не требовались.
- web-ext lint: Android minimum version предупреждение относится к data_collection_permissions (целевая платформа — desktop Firefox 140+); второе — innerHTML внутри Vue runtime для статического rendering. Код приложения не использует v-html/innerHTML для импорта, title или подсказок. Браузерные XSS-проверки literal title проходят.
- Полный npm audit: 4 high, одна не исправленная первичная проблема node-forge 1.4.0 через dev web-ext/adbkit и её downstream-зависимости. Production audit — 0. Исправленного node-forge npm-релиза не найдено; shell-quote закреплён в исправленной версии 1.12.0. Auto downgrade WXT не применяется.

Необходимые пользовательские действия: загрузить готовую сборку по README, импортировать собственный старый export.json, при необходимости войти в Mail.ru и проверить счётчик. Полный короткий ручной checklist находится в README.

## Исправления фокуса и Mail.ru

Контекстное меню использует Helvetica, при открытии мышью ни один пункт не выделен. Стрелки включают выбор с клавиатуры, движение мыши убирает его; наведение больше не зависит от оставшегося фокуса кнопки. Убрана жёлтая обводка полей, индикаторы клавиатурного фокуса кнопок сохранены. В визуальном эталоне явно учтено согласованное исправление шрифта меню.

Парсер Mail.ru принимает числовой и строковый целочисленный mail_cnt, включая строку "0" из подтверждённого ответа status=ok. Ноль означает отсутствие бейджа; noauth получает отдельное сообщение об авторизации. Unit-проверки покрывают повреждённые значения; Chrome UI smoke проверяет строки "3"/"0", noauth и credentials=include. Перехват Playwright не подтверждает фактическую передачу cookie; авторизация личного профиля остаётся ручной проверкой.
